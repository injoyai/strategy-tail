状态：已实现；本文件保留实施方案与任务顺序，实际验证结果及边界见[审核验收报告](../reviews/2026-10-19-replay-practice-acceptance.md)。

## 1. 实施边界与接入点

首版在 Lab 现有账户回测中记录过程，回测完成后按需读取并播放；不新增执行引擎、后台推送、生产依赖或框架。保留 Buyer／Seller／Cost 合同和已有交易、账户统计。

| 接入点 | 改动职责 |
| --- | --- |
| `internal/lab/builder/spec.go` 及新增记录辅助文件 | 可选的条件树记录构建入口，复用原工厂与 AND／OR 组合子 |
| `internal/lab/strategy_spec.go`、`presets.go`、`runner.go` | 按变体构建记录上下文，覆盖因子组合、已有预设及默认卖出规则 |
| `internal/lab/account_backtest.go` | 在原成交及收盘估值位置采集事件和每日持仓 |
| 新增 `internal/lab/replay.go`、`replay_store.go` | Lab 回放数据类型、校验、独立文件保存与读取 |

| `Tab2Compare.js`、新增 `BacktestReplay.js` 与 `replay.js` | 结果页内的回放入口、独立回放区域、日期状态与图表 |
| `api.js`、现有样式及相关测试 | 接口封装、窄屏与状态验证 |

不修改 `core/`、`cmd/screen/` 受保护类型，不改变 BuilderSpec／StrategySpec 的已保存策略格式。新增记录入口不改变原构建入口的类型形状与名称语义，保留现有模板、工厂等价测试。若实现发现必须改变这些边界，应先说明证据并调整方案。

## 2. 数据合同与保存方式

在 `VariantReport` 新增可省略的 `replay` 描述，仅记录格式版本与可用状态；完整每日数据不内嵌 `report.json`。现有 `listReports()` 会逐份反序列化报告，避免因列表操作加载全部回放历史。

数据放在同一次运行目录中，文件名由服务端生成：

```text
output/trades/<RunID>/
  report.json
  replay/
    variant-<index>.json
    kline/<code>.json
```

变体用报告原始序号识别，不使用界面排序位置或策略名称作为文件名；前端即使重排变体也必须保留该序号。个股 K 线由该报告所有变体共享，只保存实际买入过的股票。

| 数据 | 必需内容 |
| --- | --- |
| 回放头 | 版本、变体序号、交易日序列；与同一报告及账户点一一对应 |
| 每日收盘帧 | 原账户点、持仓市值、仓位比例、当日盈亏、每日持仓列表 |
| 持仓 | 仓位身份、代码、买入时间、数量、实际买入价、含费总成本／成本单价、估值价及价格日期、市值、浮动盈亏与收益率 |
| 成交事件 | 递增执行序号、仓位身份、日期时间、买卖方向、原始价、实际成交价、数量、费用、原因引用、分钟缺数降级标记 |
| 规则描述表 | 稳定路径、角色、规则名称、当次参数与描述；事件引用实际成功路径，避免逐日重复存整棵树 |
| 个股图表 | 本次实际加载的日 K 及预热历史，成交量、DIF／DEA／MACD；不足或无效指标使用空值，不写 JSON 非有限数 |

仓位身份在一次买入时分配，卖出沿用；同日同票卖出再买入必须得到新身份。成交顺序沿用执行顺序，不根据最终交易列表排序还原。

在 `account_backtest.go` 原买入／卖出成功位置追加实际成交事件；买入信号成立但股数为零时不生成事件。收盘完成后从 `accountState.holdings` 复制不可变持仓帧，不能保留随后会改变的指针。每次成功成交后复制原因，失败判断不累计成长历史。

费用用现有实际成交价与净收支计算：买入费用为 `BuyCost − BuyExecPrice × Quantity`，卖出费用为 `SellExecPrice × Quantity − SellIncome`；滑点已体现在成交价，不重复计入费用。浮动盈亏和收益等派生值由后端按需求口径生成，前端只格式化。

期末生成旧式 `Virtual` 交易的路径不追加卖出事件，不改变最后一帧持仓。缺日线的持仓保存上次有效价格日期；分钟缺失的判断在对应成交处记录降级。

## 3. 原因采集：只执行原判断一次

以当前 Builder 节点路径作为规则身份，例如 `buy.children[1]`、`risks[0]`、`sellSignal.children[2]`。在构建时冻结描述与参数，缺省参数沿用实际工厂语义，不使用表单目录默认值补齐。

新增带记录的构建入口：对节点包一层实现原 Buyer／Seller 接口的记录对象，内部仍调用原组件或原组合子一次，记录本次返回值及实际访问路径，`Name()` 委托原对象。组节点也记录返回值，避免把失败 AND 分支中曾经为真的叶子误当成 OR 命中原因。此处只记录，不实现另一套指标公式或交易判断。

每个账户变体有独立记录上下文；每次根 Buy／Sell 调用前重置，只保留本次临时路径。只有真实成交时，提取根节点成功路径写入事件；失败判断和分钟循环复用缓冲，不能每分钟累积一棵诊断树。原本共享的基础 Buyer 或默认 Seller 可以继续复用原对象，但记录上下文不能跨变体共享。

原因粒度与边界：

- 自由搭建：记录完整条件组命中路径、因子节点与独立风控；组合顺序、短路、单节点展平和空卖出组合行为保持原样。
- 因子组合：复用 `StrategySpec.Variants()` 的基础／单条件／组合顺序，记录各变体实际参与的规则；默认 Seller 按原顺序记录持有天数与止盈止损。
- 当前预设：`presets.go` 使用公开 `buy.And` 与原子组件，可逐层记录公开组合。组件内部的复合算法以组件为原子边界，如 `A阴线收回`；展示其真实参数和组件级描述，不伪称已追踪内部子判断。
- 记录逻辑必须调用本次已构建对象，不因解释重建并再执行另一个对象；不得改变组件内部逻辑以强行展开原因。
- 旧脚本与不透明自定义执行对象不补造路径，也不自动获得完整回放标记，原回测继续可用。

先用有副作用计数的测试 Buyer／Seller 验证调用次数、顺序、AND／OR 短路及风控优先，再接真实组件。记录前后相同输入的实际成交与每日账户须等价。

## 4. 图表、接口与报告生命周期

图表使用该次账户回测已经加载的行情副本生成并保存，预热范围取本次执行实际加载的历史，不另查更新后的行情库；每只实际买入股票生成一次，跨变体共享。指标复用现有因子／MACD 实现，日 K 图 MACD 明示其参数；默认展示 12／26／9，不暗示它一定等于所有策略节点的参数。

保存完整已加载区间的因果指标序列，读取后按回放日期截断展示；不得让图表缩放、提示框或已平仓交易摘要泄露未来数据。回放不调用现有可读取当前行情库的 `/api/kline/{code}`；原交易明细图保持原入口。

新增只读接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/report/{id}/replay/{variant}` | 读取一个变体的每日帧、事件与规则描述表 |
| `GET /api/report/{id}/replay/kline/{code}` | 按股票读取该次保存的图表数据 |

沿用报告 ID 校验及 `os.OpenRoot` 目录边界；变体序号必须是报告范围内整数，代码必须符合格式且属于该报告回放股票集合。客户端不能提交相对文件路径。未知版本、缺文件、内容不一致应明确报错，不回退到重新计算或当前行情。缺旧版回放描述时提示重新回测。

保存时先完成回放文件及现有导出，再原子发布带完整回放描述的 `report.json`；在此前不能宣布任务完成或让历史列表识别为完整报告。保存失败返回错误，不发布半份可用回放。复用现有原子写方法，勿新增持久化框架。

列表与最新报告仍只读取主报告；进入回放才读取所选变体，点击股票才读取其 K 线。缓存限于当前变体与当前股票，切换清理旧数据，不把全市场图表载入浏览器。

删除沿用现有任务锁与精确导出清理，运行目录删除自然包含 `replay/`；补测试保证不影响其他运行。旧报告、CSV／HTML 和缺少 `account` 的路径维持原行为。

## 5. 前端落点与状态约定

在现有结果页加入“回放”入口，进入后以独立回放区域替换完整结果区域，避免最终排名、收益与胜率同时可见。退出回放恢复现有结果视图；不新增顶层页签。

新增 `BacktestReplay.js` 持有当前回放日期索引、报告内变体序号、所选股票、加载／错误与播放状态。`state.currentReport` 继续作为报告来源；不修改现有 `selectedVariant` 的跨页语义。将步进、过滤与状态转换放入小型纯函数模块 `replay.js` 便于现有 Node 测试调用，图表实例与计时器保持非响应式。

- 单一日期索引派生全部可见内容：收益曲线取截至当日，持仓取当日帧，成交列表取当天，个股标记取截至当日事件；原因随可见事件读取。
- 慢／中／快采用每交易日 1500／750／250 毫秒，默认中速；使用单个可取消计时器，上一次更新完成才安排下一步，不追赶或跳过帧。
- 拖动、步进、点击详情、切换策略／报告、离开区域或页签、加载和错误均先取消计时器。策略切换保留日期，报告切换重置首日，均暂停。
- 每次异步请求使用递增请求版本；只有当前报告、变体及股票身份仍匹配的响应可以写入。读取新股票期间清空旧图或明确加载，不能把旧股票冒作新选择。
- 自动暂停检查目标日是否有实际成交，完整渲染当天后暂停；恢复从下一交易日继续，不在同一天反复暂停。
- 复用 ECharts 管理方式与现有格式化函数；抽取确有两处使用的图表配置即可，不重构整个交易页。加载／错误节点放在图表宿主外。
- 首帧与末帧按钮禁用、键盘控制、可见焦点、红涨绿跌及桌面／窄屏布局按需求验收。减少动态效果时保留步进功能，关闭装饰过渡。

## 6. 分步交付与检查

按顺序实施，每步通过受影响范围检查再进入下一步；最后统一验收，不把以下待办标为已完成。

| 步骤 | 交付与主要文件 | 最小验证及需求覆盖 |
| --- | --- | --- |
| T1 原因记录 | 构建器可选记录入口，因子组合／预设／默认 Seller 接入 | 计数器与短路测试、嵌套失败分支、风控优先、未执行分支、默认参数；R07、R15 |
| T2 账户过程 | `account_backtest.go`、`replay.go`，每日帧与成交事件 | 手工可核算行情覆盖费用、空仓、同日再买、跨年、缺数、Virtual；记录开关前后等价；R05、R06、R11、R12、R15 |
| T3 文件与 API | `replay_store.go`、`runner.go`、`reports.go`、`server.go`、`api.js` | 保存重开、旧报告、失败不发布、未知版本、非法 ID／序号／代码及路径边界、精确删除、行情更新后快照不变；R12、R13 |
| T4 播放与图表 | `BacktestReplay.js`、`replay.js`、结果页及样式 | Node 行为测试覆盖全部暂停／切换／请求失效、未来信息截断、同日多点、同日恢复不重复暂停；R01～R04、R08～R10 |
| T5 集成验收 | 真实报告、README、必要的 DESIGN／交互约定更新 | 浏览器桌面与窄屏、键盘操作、终点对账、长区间性能；R01～R15 全覆盖 |

沿用 Go 测试及 `internal/lab/web/*.mjs` 的 Node 测试基建，不新增测试依赖。Go 验证使用已有 Docker Go 1.25 环境与 `TZ=Asia/Shanghai`；阶段测试覆盖 `./internal/lab/...`，最终执行 `go build ./...`、`go test ./... -count=1`、`node --test internal/lab/web/*.mjs` 和 `git diff --check`。实际运行结果在实施时记录，本文不宣称已通过。

性能验证至少包含：一份默认 5 持仓的单年报告、一份跨 5 年且多股票多变体的报告，以及允许上限 1000 持仓的数据量探针。记录回放文件大小、保存／读取耗时、服务端峰值内存和浏览器步进情况，确认历史列表不读取回放明细、250 毫秒档不出现计时器积压、切换后旧缓存可释放。使用本地可得样本并记录实际规模；如果线性每日快照在支持范围内无法承受，应先基于测量调整分片，不默认引入数据库或事件重建体系。

实现提交前同步正式使用说明与文档状态，保持本需求文档和验收编号一致。部署只在另行授权时进行；代码验证不能替代实际浏览器验收。
