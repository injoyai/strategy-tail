# 盘感练习精简实施文档

日期：2026-10-18（Asia/Shanghai）。
状态：已实现；业务与验收以[需求文档](../specs/2026-10-18-trading-practice-requirements.md)为准，实际验证结果及边界见[审核验收报告](../reviews/2026-10-19-replay-practice-acceptance.md)。

## 1. 落点与复用

新增独立练习状态，不让 `core.Backtest` 代替人工交易，不依赖回测回放数据。仅使用现有 Go 标准库及已安装前端能力，不新增依赖，不修改 `core/`、`cmd/screen/` 受保护类型及已有策略格式。

| 当前源码／拟新增文件 | 职责 |
| --- | --- |
| `builder_store.go`、`builder/spec.go` | 读取所选策略并构建原买入条件 |
| `commonPullDayKlines`、`common.Market沪深主板.LocalCodes()`、`core.Cost`、现有因子实现 | 同源本地行情、本地主板股票列表、费用及指标，不使用当前在市列表替代历史本地样本 |
| 新增 `practice.go`、`practice_store.go`、`practice_server.go` | 抽题、状态转换、快照与原子存储、匿名响应及接口 |
| `server.go`、`task.go`、`runner.go` | 注册 Store／接口；出题接入现有后台任务锁与生命周期 |
| 新增 `Tab7Practice.js`、`practice.js` | 练习／历史／复盘视图及少量可测试前端状态逻辑 |
| `constants.js`、`app.js`、`store.js`、`api.js`、`index.html`、现有样式 | 增加 `practice` 页签与接口，原页签编号和 slug 不变 |

`BuilderSpec.Validate("run")` 要求卖出侧，不能直接用于练习。保留完整策略快照，用仅保留版本、名称和 Buy 的临时投影调用既有 `Validate("save")`，再要求 Buy 非空并调用 `Buyer()`；不修改源策略、不放宽回测校验，也不为了通过校验虚构卖出规则。

`Tab3Trades` 会请求卖出后行情并显示完整交易，现有 `/api/kline/{code}` 的截止时间由客户端提供。练习使用独立数据入口，复用 ECharts 挂载／清理、布局和原指标计算；不能直接嵌入整个交易详情组件。MA／MACD 复用项目算法，保持原始价格单位和缺省参数语义。

## 2. 抽题与快照

出题请求只接收策略 ID、所读策略版本和起止年份，年份校验沿用现有范围。股票取本地股票列表并排除指数，不新增股票池选项。使用 `common.ResolveRuntimePath` 定位存储；所有行情读取只访问本地，不隐式更新。

后台出题持有现有 Runner 任务锁，阻止与 Web 行情更新／研究任务同时运行；通过 `beginTask`／`launchTask` 收尾，取消不发布可用题目。逐股加载截至开题截止点的完整日线，逐日以 `ks[:i+1:i+1]` 调用原 Buyer，仅评估所选年份内的日期。每只股票独立构建 Buyer、独占求值缓冲，不修改行情源；上下文因子沿用已有按时点查询能力及数据来源限制。

用标准库 `math/rand/v2` 对命中机会做蓄水池抽样：第 n 个命中以 1/n 概率替换当前候选；保留候选的行情副本，内存只容纳当前股票和一个候选，不建立全市场信号列表。测试注入随机选择函数，避免用随机分布碰运气断言。逐股票错误纳入覆盖记录，未知策略错误／panic 不当作不命中；没有候选时明确返回无匹配。

选中的股票保存同一次加载的原始完整行情及所需图表指标，覆盖预热、信号日、之后全部可用日线；截止点只纳入已完成日线。若读取到未收盘当日行情，不将其作为“收盘价”候选或后续帧。保存来源、加载时间和实际最后日期；后续交易、复盘、重练均读取此快照，不再读取行情库。行情检查日期递增、重复日期和有效价格；指标不足用 null 表示，不将 NaN／Inf 写入 JSON。指标按完整历史因果计算后再截断输出，不能按当前视窗重置 EMA。

任务名建议 `practice_prepare`，阶段为准备／扫描股票／保存。接入 `TASK_LABEL`、`taskProgress` 及 `pollStatusOnce` 的专门完成分支，完成后刷新练习而非读取回测报告。公开进度只含阶段和数量，不公开当前代码、候选日期、原始失败详情；失败详情留到已结束复盘。出题之外的逐日操作使用短时 Store 锁，不长期占用 Runner 锁。

## 3. 存储与状态转换

```text
data/lab/practice/<opaque-id>/
  market.json    # 不可变私有行情与指标快照
  session.json   # 策略／费用快照、版本、阶段、当前位置、操作与结束原因
```

这两类是练习运行状态，放在 `data/`；首版不额外导出报告。ID 使用现有前缀随机 ID 模式，不含股票／信号日期。创建时先写完整 `market.json`，再原子发布可用 `session.json`；用格式版本识别数据，缺失／损坏／未知版本报错，不重新下载或补造。

会话保存：请求 ID、策略来源 ID／版本及完整定义、费用副本（Slippage=0）、预算 20000、行情快照标识、信号／当前／买卖索引、股数与收支、递增 revision、操作 ID 和结束原因。准备中的元数据也落盘，刷新能找到任务；重启后无执行者的准备记录标为中断，可显式重新出题，不伪装为可继续练习。首版面向单个 Lab 服务实例，Store 进程锁不宣称支持多实例共享写。

生命周期用 `preparing / active / finished / failed / cancelled`，active 内阶段用 `waiting / holding / sold`：

| 操作 | 条件与结果 |
| --- | --- |
| next | active；有下一根则 current+1；没有则 finished，reason=data_end，不虚构卖出 |
| buy | waiting；服务端用当前位置收盘价算含费最大整手量，成功后 holding |
| sell | holding 且 current>buyIndex；按当前位置收盘价全部卖出，转 sold，仍 active |
| skip | waiting；finished，reason=skipped |
| finish | 任一 active 阶段；finished，记录未交易／未平仓／已卖出的真实结果 |
| retry | 已结束题；复制其快照为新 ID，当前位置回到信号日、无成交，保存 sourceSessionId，标记重练 |

到达最后一根行情时仅返回 `canAdvance=false`，仍允许当日买卖；下一次 next 或主动结束才收口。客户端不提交价格、股数、目标日期、代码或盈亏，只提交动作；服务端检查合法转换并计算结果。

复用 `atomicWrite` 与安全 ID／目录边界模式。每个命令携带 `commandId + expectedRevision`；在 Store 锁内读取、校验、生成新状态并原子写入后返回。相同命令 ID 与内容重试不重复执行，返回权威状态；ID 内容不符或旧 revision 返回冲突，前端读取而不自动重放。创建同样按 requestId 幂等，忙碌拒绝不产生半个可用题目。写盘失败不推进内存状态。

完整成交复用 `Cost.BuyCost`／`SellIncome` 和 `Trade.Profit`／`ProfitAmount`；股数从不含费上界按整手下调到含费预算内。持有天数直接做日 K 索引差，不使用按自然日近似的 `Trade.HoldingDays()`。浮盈亏按需求的逐日收盘口径计算；首版无跨题汇总，不新写一套胜率／盈亏比。

## 4. 接口与未来信息隔离

| 拟新增接口 | 行为 |
| --- | --- |
| `POST /api/practice` | 创建／幂等恢复出题任务，返回不含身份的会话 ID |
| `GET /api/practices` | 练习摘要、阶段、恢复入口；进行中的题目保持匿名 |
| `GET /api/practice/{id}` | 已揭示日 K／指标、相对索引、当前仓位／收益、合法操作、revision |
| `POST /api/practice/{id}/actions` | next／buy／sell／skip／finish 命令，返回保存后的匿名或终态视图 |
| `GET /api/practice/{id}/review` | 仅 finished 可读，揭示身份、实际日期、结果与结束日后最多 20 根 K 线 |
| `POST /api/practice/{id}/retry` | 仅 finished 可重练；新记录使用原快照，不重新筛题 |

活跃视图从私有持久对象显式投影，不直接 JSON 序列化整个 session 或 market；不返回股票身份、真实行情日期、总未来根数、数据截止日期、未揭示指标或终局指标。相对索引以信号日为 0，背景为负数；当前日之前全部已揭示数据可以查看，客户端不能请求任意更大截止索引。持仓最大浮盈亏只统计到 current，已卖出则固定截止于 sellIndex。

复盘上界为 `min(endIndex+20, snapshotLastIndex)`，保留此前完整过程；已卖出收益始终固定。进行中访问 review 返回冲突；无效动作／参数返回 400，过期版本 409，不存在 404，存储损坏 500。错误文本不回显匿名题目的私有路径、代码、真实日期或原始行情错误。

写接口沿用 `requireSameOrigin`、`decodeStrict`、请求体限额及合法 ID 校验；客户端不能提供文件路径。市场快照不挂静态目录，不提供通用下载接口；身份揭示权限由服务端状态决定。现有研究行情 API 保持原合同，盲练并非限制本地用户主动查找数据的安全沙箱。

## 5. 前端接入

新增顶层“盘感练习”页签，编号 7、slug=`practice`；复用原导航和单一 h1 机制，保留六个既有入口。URL 只保存不透明会话 ID；离开页面不结束或自动推进，刷新后从服务端恢复。历史列表显示已完成／进行中／重练标记，进行中不显示本题真实身份。

顶部紧凑展示策略与年份选择、当前相对交易日、阶段和操作；核心日 K／量／MACD 图进入首屏。图表用服务端已裁剪数据、相对轴、MA5／10／20及已发生买卖标记；收盘模拟、费用、同日禁止卖出等规则就近说明。sold 仍保留“下一交易日”和“结束本题”，不自动跳复盘。

`practice.js` 只处理视图与操作状态，不在前端重算正式成交。请求中禁用重复动作、未保存不乐观推进，失败允许复查／重试；切换会话及异步读取用请求版本丢弃旧响应。使用既有图表生命周期，提示节点放在图表宿主外；检查键盘、320／390／1440 像素宽度、焦点及红涨绿跌。实施时按新入口同步更新 `DESIGN.md`／`UX-CONTRACT.md`，不在本方案阶段将待实现 UI 写成已存在事实。

## 6. 实施顺序与验证

1. **状态与存储**：先用固定日 K 写状态转换、含费预算、收盘成交、T+1、末日决策、未平仓估值测试；再补原子写失败、重启恢复、命令重试和 revision 冲突。
2. **抽题与接口**：接所选策略与任务锁，验证买入侧单独校验、时点前缀、受控随机替换、覆盖／取消；先测本地小样本扫描耗时与内存，不为首版新增全市场信号缓存。API 测试直接检查响应 JSON 不含身份、真实行情日期及未来哨兵数据，覆盖状态／列表／错误与禁止提前 review；更新行情／策略／费用后旧题与重练保持一致。
3. **界面与回归**：完成匿名练习、卖后逐日观察、终态复盘、历史恢复与重练。沿用现有 Node 测试和浏览器验证方式，覆盖请求竞态与失败恢复；最后核对需求 P01–P12。

建议在既有 Linux／Docker Go 环境运行 `go test ./internal/lab/...`、`go build ./...`、`go vet ./internal/lab/...`，前端运行 `node --test internal/lab/web/*.mjs`，并执行 `git diff --check`。新增测试用 `t.TempDir()` 与固定行情，禁止改写真实行情或策略库；具体结果在实施交付时记录，本次只验证文档引用与差异。
