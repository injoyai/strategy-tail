# strategy-tail 精简整改实施方案

日期：2026 年 11 月 23 日。

对应[审查报告](审查报告.md)，代码基线为 `c314f05a9238485ccdc587b4e0afaeb8f3fc1cfc`。本方案只处理 R1 至 R4，目标是恢复构建可复现性并修正已经复现的计算问题。状态：待实施。

## 实施边界

沿用现有项目、数据源、策略接口和报告形式。局域网访问、监听地址和部署入口保持现有使用方式。本轮不增加登录、权限、认证代理、访问限制或其他使用门槛；已有同源校验保持原状。

不合并回测引擎，不升级整个技术栈，不大规模移动代码，不引入公司行为平台、撮合系统或数据治理框架。必要说明直接放入现有 README 和结果说明。

## 实施顺序

| 步骤 | 对应问题 | 可独立验收的交付 |
| --- | --- | --- |
| 1 | R1 固定 SDK | 兼容提交记录、现有构建入口核对、构建说明 |
| 2 | R2 修正 RSI | 零跌幅处理及指标和卖出条件回归测试 |
| 3 | R3 修正盘中快照 | 旧引擎字段修正及时间一致性测试 |
| 4 | R4 保留跨年有效数据 | 加载和调用方调整、跨年账户回归测试 |

每一步单独提交，便于定位结果变化。步骤 2 和 3 不依赖步骤 4 的数据加载调整。

## 步骤 1 固定兼容 SDK

保留 `go.mod` 和 `go.work` 使用 `../tdx` 的开发方式。新增一个简短的 `tdx.rev` 文件，记录完整 SDK 提交，作为兼容版本的单一来源。初始候选使用本次通过测试的 `df1ef9f455b15544028585998e366dc921817a22`。

在现有 `deploy.sh` 获取 SDK revision 的位置增加核对：目录缺失或 HEAD 不匹配时，提示期望和实际提交并结束本次构建。只检查和提示，不自动切换、清理或覆盖使用者的 SDK 工作区。保持已有构建版本记录逻辑。

README 补充首次准备相邻 SDK、核对提交以及运行测试的步骤，直接引用 `tdx.rev`。SDK 后续升级时，同一变更更新版本记录并执行相关回归测试。

预期涉及：`tdx.rev`、`deploy.sh`、`tests/deploy_test.py`、`README.md`。不为此新增通用依赖锁定工具或 CI 平台；已有 CI 可复用同一版本记录。

验收：

- 在新准备的两个相邻目录中，按文档可以构建 `cmd/lab`。
- 匹配提交通过核对；缺失 SDK 或不匹配提交给出明确提示。
- 检查失败不会修改 SDK 目录，也不会继续部署。
- 部署脚本既有行为测试保持通过。

## 步骤 2 修正整数 RSI

修改 `lib/extend/model_kline.go` 的 `Klines.RSI`，在每个窗口形成后完整处理上涨和下跌分支：有上涨且没有下跌时返回 100；只有下跌时返回 0；两者均存在时保留现有计算和整数截断。

完全横盘时明确采用整数实现的零值约定 0，避免沿用旧窗口值；不将其改成浮点实现的 50。两个实现继续保留各自已声明的输出口径，注释说明边界。数据不足和非法周期继续采用现有处理，不改策略默认参数。

在 `lib/extend` 增加直接验证公式边界的测试，在 `strategies/sell` 增加 `ARSI恢复` 的行为测试。不要仅修改旧快照期望而省略原因断言。

| 用例 | 周期 | 期望 |
| --- | --- | --- |
| `[10, 11, 12]` | 2 | RSI 为 100，阈值 75 的卖出条件触发 |
| `[10, 9, 10, 11]` | 2 | 最后窗口 RSI 为 100，不残留 50 |
| `[12, 11, 10]` | 2 | RSI 为 0 |
| `[10, 10, 10]` | 2 | RSI 为 0 |
| `[10, 11, 9]` | 2 | 保留整数截断结果 33 |
| 不足周期或非法周期 | 按现有接口 | 保持原有行为 |

验收命令：`go test ./lib/extend ./strategies/factor ./strategies/rule ./strategies/sell`。

该修复会改变使用整数 RSI 的部分历史信号，属于预期结果变化。旧报告不覆盖，需要比较时重新运行相同输入。

## 步骤 3 修正旧引擎盘中快照

局部修改 `core.Backtest.Do` 的分钟快照构造，以账户引擎已有行为为参照。累计量价仍只使用截至当前分钟的数据。

- `Time` 和 `Unix` 均对应当前分钟。
- `Turnover` 先清零，再根据当前累计成交量和已知流通股本重算；遵循项目的手与股换算。
- 缺少有效流通股本时保留缺失状态，不能沿用全天换手率。
- 核对 `Last` 的前收盘口径，使用已知日线前收或历史收盘，不能将当前分钟开盘价当作前收。必要时在聚合后显式设置，防止 SDK 聚合方法覆盖。
- 保留私有快照和当日结束恢复原始日线的做法，避免修改输入数据。

先在原函数内完成修复。如果只是数行字段赋值，不抽象新的快照框架。账户引擎已有正确逻辑时只增加对照测试，不为了形式统一改动它。

增加以下测试：

1. 前一日买入，次日 09:31 调用 Seller，断言两种时间字段一致。
2. 流通股本为 1 亿股、累计成交 100 手时，换手率为 0.01%，不等于全天 10%。
3. 仅改变 09:31 之后的分钟数据及全天统计，09:31 的快照和信号保持一致。
4. 多笔持仓、多交易日执行后，原始日线内容不变。
5. 无流通股本、无分钟数据的现有降级路径仍可解释且不读取未来值。

验收命令：`go test ./core ./internal/lab`。测试比较快照和信号语义，不强求不同执行模式产生相同成交时刻。

## 步骤 4 保留跨年有效数据

目标是消除“某年正常查询但没有行情，导致其他年份有效数据也消失”的行为，同时保留查询错误的可见性。不能把所有加载失败改成成功。

### 区分空数据与查询失败

在 `internal/researchrun/runner.go` 的加载层，用稳定的内部标识区分以下情况，不依赖错误文本匹配：

| 情况 | 处理 |
| --- | --- |
| 查询成功，目标年份存在有效行情 | 交给执行层 |
| 查询成功，目标年份没有行情 | 记录空年份，保留同票其他有效年份 |
| 查询报错或数据无效 | 保持明确失败，不伪装成正常空年份 |
| 所有请求年份均无行情 | 不创建可交易数据，保留原因说明 |
| 任务取消 | 按现有取消语义退出 |

继续使用现有 Failure、Coverage、YearCoverage 等输出能力，避免为了分类新增一套报告协议。

### 调整账户与逐笔研究入口

账户回测优先复用已有 `ForEachCodeYearData` 的逐年加载方式。将每只股票成功加载的年份按时间排序，只使用最早有效年份的一份历史预热数据，再拼接请求年份的有效日线。不要把各年的 `His` 全部追加，避免重复日期和重复交易。

处理并发回调时，在收集阶段保持必要同步，汇总完成后再按日期整理。继续验证日期顺序和重复日线。覆盖统计应按实际可用股票和失败年份汇总，不能把年份数直接当成股票数。

账户资金和持仓仍跨年连续。无行情时不能凭空成交，也不能只凭数据缺失推断已退市或自动清仓；已有沿用上次价格的估值行为继续明确披露。不得使用未来年份重新出现的价格填补更早的缺口。

旧逐笔研究入口 `researchrun.Run` 的 `runCode` 同步检查正常空年份处理，保留其他年份结果。其他依赖 `ForEachCodeData` 整票回调契约的调用方不应被无差别改变；先检查调用方，再决定局部迁移或复用加载逻辑。

本步不会建立完整的历史上市、退市资格模型，也不宣称消除了所有幸存者偏差。

### 回归样本

| 场景 | 必须满足的结果 |
| --- | --- |
| 只有 2024 年有数据，请求 2024 年及 2024—2025 年 | 两次都保留 2024 年有效样本 |
| 只有 2025 年有数据，请求 2024—2025 年 | 2025 年可以参与，预热不足按策略原规则处理 |
| 中间年份为空，后续恢复行情 | 不删除前期样本，不填造缺口行情，不读取未来价格 |
| 所有年份为空 | 无交易，原因清楚，任务正常结束 |
| 某年查询返回错误 | 错误可见，不能宣称该年正常完成 |
| 多年数据有重叠预热区间 | 不重复日线、不重复交易 |
| 跨年持仓 | 现金与持仓连续，不因切年重置 |

增加一条关键断言：延长回测结束年份，不能改写原区间内已经发生的因果信号与实际成交。原结束日的期末估值、虚拟平仓和终点汇总不属于该断言，延长区间后这些终点结果可以自然变化。

验收命令：`go test ./internal/researchrun ./internal/lab`。文档同步说明空年份与加载错误的处理，继续使用现有覆盖提示，不新增数据质量评分或审批步骤。

## 整体验收与交付

每步完成对应测试后，最后执行一次完整回归：

```bash
go test ./...
node --test internal/lab/web/*.mjs internal/chartui/*test.mjs
python3 tests/deploy_test.py
go build -o /tmp/strategy-tail-lab-check ./cmd/lab
```

这些命令是实施后的验收要求，不代表修复已经完成。测试应使用夹具；无需连接真实行情数据库，也无需启动部署。Lab 测试需要允许临时回环 HTTP 监听，不能把权限限制误判为业务测试失败。

最终交付包含四项修复、对应回归测试、构建和行为说明。检查差异，确保没有改变网络访问方式、没有无关依赖升级或架构重构。历史报告保留原样，新旧结果差异按 RSI、快照和样本范围分别说明。

公司行为、特殊证券交易规则、容量和部分成交暂不实施；它们仍是审查报告中按实际研究需求启动的后续事项。
