# Lab 自由组合策略搭建器设计

日期：2026-10-13（Asia/Shanghai）。
状态：用户已确认业务设计；核心实现、界面调整与验收修正已完成自动化验证、桌面／窄屏浏览器验收，并已部署到本地 Lab（2026-10-14）。

## 1. 目标与确认结果

用户主要调整参数进行回测，希望从熟悉的 Go 策略组件出发，在 Web 中自主添加条件并组成策略。固定九个条件的勾选开关不能满足该需求。

本次 GrillMe 访谈确认如下：

| 决策 | 已确认行为 |
|---|---|
| 条件来源 | 从现有 Go 买入、卖出组件库选择，不在本次引入新的公式语言 |
| 组合方式 | 支持 AND／OR 条件组，可嵌套；同一组件可添加多次，各自配置参数 |
| 策略保存 | 支持命名保存、加载及复制多套策略 |
| 空条件 | 空买入、空卖出与空条件组不能直接回测；基准行为必须显式选择 |
| 回测草稿 | 可直接回测当前有效编辑内容；只有点击保存才更新策略库 |
| 卖出风控 | 风控由用户自主添加，独立触发；策略卖出信号支持 AND／OR 分组 |

术语以根目录 `CONTEXT.md` 为准。

## 2. 用户操作

主入口沿用 Lab 的回测配置页面，提供新建策略、选择已保存策略、保存、另存为和运行回测。编辑区由买入条件树、策略卖出信号树及独立风控列表组成。

每个条件组提供“添加条件”“添加分组”“全部满足／任一满足”。添加条件时从组件库选择类型，随后按该组件的参数定义生成输入。条件实例可以删除；添加三个不同周期的均线条件不需要修改代码或预置第三组字段。新加同类条件具有独立参数，修改其中一条不会影响其他实例。

布局复用当前组件、按钮和配色，采用紧凑工具界面。默认买入组为全部满足，默认策略卖出信号组为任一满足，用户可以修改。风控区说明“任一风控满足即可触发卖出条件”。仅展示用户添加的条件，不预先铺满所有组件并要求取消勾选。

提供当前 `cmd/backtest` MACD 策略作为可加载模板，帮助用户从熟悉的规则开始；模板加载后就是普通可编辑条件树，可以任意添加、删除和分组。另提供新建空白策略。

示例规则结构：

```text
买入：全部满足
  价格范围
  任一满足
    MACD 连涨
    均线向上：20 日
  均线向上：30 日
  均线向上：60 日

策略卖出信号：任一满足
  MACD 反转
  其他已接入卖出信号

独立风控：任一触发
  用户添加的止损规则
  用户添加的持仓期限规则
```

这是组合形式示例，不构成默认开启这些风控的要求。

## 3. 条件目录与动态表单

后端提供显式组件目录及工厂映射。目录包含稳定组件标识、中文名称、买入／策略卖出／风控分类、参数类型、单位、默认值、范围语义和数据依赖。前端按目录渲染通用条件编辑器，不维护固定 MACD 字段清单或固定组件实例数量。

接入前盘点 `strategies/buy` 和 `strategies/sell` 的公开组件，覆盖可由现有回测数据执行的价格、市值、成交量、均线、MACD、RSI、布林及卖出组件。组件存在但所需数据或适配尚不可用时，应说明不可用原因，不能显示成可运行后再静默忽略。目录和工厂对应关系应有检查，避免只为当前模板注册九种条件后宣称完成组件库接入。

组件定义仍复用现有 Go 实现。不同类型的结构体、数字别名、列表及无参数组件需要明确适配，不能仅靠反射猜测参数默认值、单位或范围。新增已适配组件应通过后端目录与工厂扩展，不要求再次修改前端条件布局。

参数遵循已有业务语义：已有范围参数使用 Min／Max，并保留零上限等退化规则；已有固定周期按其原组件行为映射，不擅自修改核心类型。百分比在界面显示百分数，执行时使用组件要求的比例；价格、市值、股数等采用已定义的单位。

## 4. 组合及风控执行

买入条件树复用 `buy.And`／`buy.Or`，策略卖出信号树复用 `sell.And`／`sell.Or`。本次不新增自定义指标计算，也不把任意表达式解释执行作为条件搭建途径。

独立风控仍是已有 Seller，与策略卖出信号组合成：

```text
sell.Or{独立风控规则..., 策略卖出信号组合}
```

风控先求值，保持 `PROJECT_RULES.md` §6.3 的约定。组件目录须区分风控与普通策略卖出信号，服务端验证该分类；仅靠前端限制不能防止把止损送入 AND 组。止损达到阈值时，即使 MACD 反转信号未成立，也应满足卖出条件。实际交易继续遵守引擎的 T+1、分钟线、成本和仓位规则。

未添加风控时不自动塞入固定风控。显式“持有至期末”只表示策略不主动发出卖出信号，独立风控仍可触发；期末估值沿用核心引擎 Virtual 标记，不伪装为真实成交。

空买入、空策略卖出与无独立风控的组合不能运行；当已有有效独立风控时，卖出侧并非空配置。若用户明确选择“全部样本买入”或“持有至期末”，以可识别的显式规则记录其选择。任何已添加的空分组都不能借用空 AND／OR 的数学结果悄悄成为有效规则。

## 5. 保存、编辑与回测快照

已保存策略与当前编辑草稿分开。加载得到可编辑副本，修改不会立即覆盖策略库。运行回测只提交当前有效草稿；点击保存才持久化策略。另存为将当前草稿保存为新的策略身份，不能覆盖源策略。运行配置在点击回测后选择，确认后才提交。

运行报告保存完整实际策略快照：条件实例及其参数、分组结构、独立风控、显式基准选择，以及本次运行范围。快照不能只存策略 ID 并在查看旧报告时读取策略库的最新内容。修改或复制策略不得改变已完成报告。

策略定义使用独立版本和稳定标识，沿用现有本地文件 Store、原子写入及运行时目录解析模式，建议存放在 `data/lab/strategies/`。报告继续进入已有 `output/` 目录。保存失败保持草稿并提供可重试错误；多页编辑不得悄悄覆盖新版本。

快照用于说明该次使用的规则，不能承诺以后数据、组件代码或运行配置变化时仍得到完全相同的数值。报告应保留当次有效参数与已有数据覆盖信息。

## 6. 兼容性与实现边界

当前 `StrategySpec` 是预设加 AND 因子过滤，不能直接冒充支持嵌套条件树。应建立 Lab 自身的版本化搭建器定义，并复用现有运行器执行，避免破坏既有简单模式契约。

旧 MACD 参数、因子组合、高级脚本与历史报告保持可读。加载旧 MACD 模板或转换其开关时，应准确保留已启用规则和参数；不能将旧报告的未勾选条件重新加入。新搭建器报告按自身来源显示结构，不复用简单模式的单条件对照说明。

回测与数据更新、因子研究、组合研究继续共享同一个任务锁及公共进度条。保存策略不是长任务，不额外占用行情任务锁；保存动作也不自动启动回测或更新。

遵守以下实现边界：

- 只在 Lab 层适配条件定义、目录、存储和界面，复用 Buyer／Seller 与核心回测引擎。
- 不修改 `PROJECT_RULES.md` 保护的核心类型，不整理 `cmd/backtest/main.go` 草稿。
- 统计沿用 `core.Stats`，MACD 沿用共享指标实现，不在前端重算正式结果。
- 不新增生产依赖，不引入拖拽框架或新的解释执行语言。
- 写入、回测入口验证同源、负载大小、规则树规模及深度、参数、组件角色和标识；不接受任意文件路径或未知组件。
- 未知配置版本、不可用组件、非法参数及空分组均明确报错，不静默删除条件以便运行。

## 7. 验收场景

1. 新建空白策略，空条件不能启动回测；错误明确指向需要补充的买入或卖出规则。
2. 添加 MA20、MA30、MA60 三个同类实例，修改、删除其中一条不影响其他实例，保存加载后完整恢复。
3. 构建 `A AND (B OR C)`，用可判定样本验证分组行为；与 AND 平铺不同的情况能得到正确结果。
4. 止损与 MACD 卖出信号共同存在，止损已成立而 MACD 未成立时仍满足退出条件；交易执行继续遵守 T+1。
5. 将风控组件放入策略卖出 AND 组的直接 API 请求被拒绝或要求改为独立风控，不能只限制界面操作。
6. 加载已保存策略，修改参数直接回测，策略库保持原值；新报告显示修改后的实际规则。随后显式保存才更新库中定义。
7. 另存为策略后，原策略与旧报告均不改变；保存失败或版本冲突不丢失当前输入。
8. 原 CLI MACD 规则转换成模板后，构造出的 Buyer／Seller 与直接代码组合等价；在隔离数据上逐笔比较成交。
9. 显式“全部样本买入”和“持有至期末”可运行，并与空配置区分；期末交易显示 Virtual 标记。
10. 所有长任务保持互斥，任务进度仍只有一个；后端繁忙冲突与界面状态一致。
11. 旧报告能读取，模板转换忠实保留原开关；未知组件、非法角色和过深规则树会在执行前被拒绝。
12. 桌面与窄屏无横向溢出，主要操作可见；添加、删除、分组及参数输入可用键盘操作，输入错误与控件关联。
