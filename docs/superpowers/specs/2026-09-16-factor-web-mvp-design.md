# 因子 Web 入门工作流设计（MVP）

> 日期：2026-09-16
> 状态：多条件 AND 方向已确认，待实施
> 范围：Strategy Lab 的因子理解、多条件 AND 过滤和对照回测
> 本文只定义产品与技术边界，不代表已经实现

## 1. 背景

当前 Strategy Lab 已支持：

- 在浏览器中编辑 Go/Yaegi 策略脚本并运行回测；
- 从因子目录选择因子，运行逐日横截面 IC 分析；
- 展示 IC 时序、回测汇总和交易明细。

但日常使用仍有两个门槛：

1. 想把因子加入原有 `core.Buyer`，仍然需要修改 Go 脚本；
2. 页面直接出现 `Factor`、`Days`、`Window`、`Spearman IC` 等术语，用户尚未形成“因子是什么、如何使用”的稳定心智模型。

本设计不把 Strategy Lab 改造成复杂的量化平台，而是在现有四个 Tab 上增加一个简单模式，让用户无需写代码即可完成：

```text
逐个理解因子 → 看历史分组表现 → 组合 2～4 个 AND 条件 → 对照回测
```

## 2. 目标与非目标

### 2.1 MVP 目标

1. 用户不读公式，也能理解“因子是每只股票在某一天的一个数值”。
2. 用户能看懂因子值高低与未来收益的历史关系，但页面不把统计关系描述为买卖建议。
3. 用户选择一个已有买入策略，再添加 2～4 个因子过滤条件，所有条件同时满足。
4. 系统自动生成基准、各单条件和全部条件组合变体，既比较最终组合，也保留条件归因。
5. 运行配置和结果报告保存完整配置快照，保证结果可复查。
6. 原有脚本编辑器保留为高级模式，现有脚本/API 不被破坏。

### 2.2 MVP 明确不做

- 不做多因子加权、标准化、综合评分或自动选权重；
- 不做 TopN、候选集内排名或持仓 TopN；
- 不做组合权重、资金分配和定期调仓；
- 不做拖拽式无限嵌套 AND/OR 编辑器；首版只支持固定 AND；
- 不做策略库的创建、复制、删除等完整 CRUD；
- 不做财务因子历史研究；
- 不改变现有回测成交模型；
- 不取消 Go/Yaegi 高级模式。

这些能力需要额外的 Universe、Signal、Portfolio 和执行时点契约，不能用首版表单假装已经解决。

## 3. 首版概念模型

### 3.1 用户只需要理解四个概念

| 用户界面名称 | 一句话解释 | 当前代码概念 |
|---|---|---|
| 观察指标 | 对一只股票某一天状态的数值描述，例如“近 20 日涨了多少” | `core.Factor` |
| 买入条件 | 回答当天是否出现候选买点 | `core.Buyer` |
| 因子过滤 | 在已有候选买点中，按观察指标的数值范围继续筛选 | `buy.A因子过滤` |
| 卖出规则 | 买入以后何时退出 | `core.Seller` |

页面正文优先使用“观察指标”，在标题或帮助中补充“量化研究中通常称为因子”。代码、API 和高级统计区域继续使用 `factor`，避免修改现有技术契约。

### 3.2 因子不是买入信号

首版页面固定展示以下解释：

> 因子只负责给股票打出一个数值，不会自动决定买入。只有把这个数值设置成过滤条件以后，它才参与策略判断。

示例：

```text
20 日动量 = 0.08

含义：当前收盘价比 20 个交易日前高约 8%。
它描述的是状态，不等于“应该买入”。
```

### 3.3 未来收益不是因子输入

“未来 5 日收益”只用于回答“当时的因子值与后来的收益是否存在历史关系”，不能参与当天的因子计算。页面在收益窗口旁固定显示：

> 后续收益只用于评价，不会进入策略判断。

### 3.4 IC 放入“统计详情”

主界面不再用 IC 作为第一信息。默认先展示五组收益对比，并用自然语言解释方向：

- 从低值组到高值组整体上升：历史上因子值越高，后续收益倾向越高；
- 从低值组到高值组整体下降：历史上因子值越低，后续收益倾向越高；
- 各组交错：当前样本没有显示清晰的单调关系。

为避免主观判定，只有 `Q1 ≤ Q2 ≤ Q3 ≤ Q4 ≤ Q5` 时显示“高值组整体更高”，只有反向单调时显示“低值组整体更高”；其他情况统一显示“各组交错”。不使用平滑线或容差把非单调结果包装成清晰关系。

IC 均值、标准差、t 值和每日 IC 曲线收进“查看统计详情”。页面只解释正负方向，不给出“强因子”“可交易”等自动评级，也不设置未经验证的通用阈值。

## 4. 信息架构

保持现有四个 Tab，降低迁移成本：

1. **策略配置**：默认进入简单模式；高级模式保留脚本编辑器。
2. **回测结果**：主展示原策略与多条件组合策略，并提供各单条件归因。
3. **交易明细**：沿用现有明细和 K 线钻取。
4. **因子研究**：先解释、再分析、最后加入策略。

Tab 状态使用 URL 查询参数保存，例如 `?tab=factor`，刷新和返回后仍停留在原位置。实现时采用标准 `tablist/tab/tabpanel` 语义及方向键操作。

### 4.1 策略配置页

页面提供“简单配置 / 高级脚本”二选一切换，默认简单配置。

简单配置首版只有四块：

1. 基础策略：从显式注册的少量预设 Buyer 中单选；
2. 因子条件：默认两条、最多四条；全部使用 AND，不提供 OR 或嵌套分组；
3. 卖出规则：复用现有持有天数、止盈、止损；
4. 运行范围：年份和样本池，复用现有配置。

高级脚本保持现状，不尝试把任意 Go 脚本反向解析成表单。

### 4.2 因子研究页

采用“认识 → 验证 → 使用”三段式，而不是先展示统计公式：

```text
┌──────────────────────────────────────────────────────────────┐
│ 因子研究                                                     │
│ 选择一个观察指标，看看它过去与后续收益有什么关系。           │
├───────────────────────┬──────────────────────────────────────┤
│ ① 认识这个指标        │ ② 选择研究范围                       │
│ 20 日动量             │ 2022—2025 · 随机 300 只              │
│ 近 N 日价格涨跌幅      │ 观察后续 5 个交易日                  │
│ 示例：0.08 = 上涨 8%   │ [开始分析]                            │
├───────────────────────┴──────────────────────────────────────┤
│ ③ 五组历史表现                                               │
│ 低值组  Q1  Q2  Q3  Q4  Q5  高值组                           │
│ [分组收益柱状图]                                             │
│ 历史描述：高值组的后续收益整体更高。                         │
│ [查看统计详情]          [添加到策略条件]                      │
└──────────────────────────────────────────────────────────────┘
```

“添加到策略条件”不会立即运行回测，而是把因子和参数追加到“策略配置”页，并把焦点移动到新增条件。用户确认阈值、补齐至少两个条件后再运行；相同 kind/days 已存在时聚焦原条件，不重复添加。

## 5. 关键交互

### 5.1 因子选择

因子下拉沿用 `GET /api/factors`，但目录项需要补充面向用户的元数据：

```json
{
  "kind": "momentum",
  "name": "N日动量",
  "category": "趋势与动量",
  "description": "当前收盘价相对 N 个交易日前的涨跌幅",
  "parameterLabel": "回看天数",
  "defaultDays": 20,
  "unit": "ratio",
  "example": "0.08 表示上涨约 8%"
}
```

原则：

- 列表按“趋势与动量、波动、量能、K 线形态、位置、相关性”分组；
- 常用因子优先展示，其余收在“更多指标”；
- 切换因子后同步更新说明、单位、示例和参数名称；
- 不把 Go 类型名或 registry kind 当作主标签；
- 加载失败时保留页面结构，显示“因子目录加载失败”和“重新加载”。

### 5.2 多个因子过滤条件

不直接要求用户填写 `Min=-1e9` 或 `Max=1e9`。界面使用三个操作符：

- 大于等于；
- 小于等于；
- 介于两者之间。

前端提交明确的操作符，后端负责映射为 `A因子过滤{Min, Max}`。显示单位由目录元数据决定：百分比因子在界面输入 `8%`，提交时转换为 `0.08`；K 值按 `0–100` 展示；相关系数按 `-1–1` 展示。

策略配置页把每个条件显示为独立编号卡片，中间使用明确的“并且（AND）”连接符。用户可以添加或删除条件，但首版不提供拖拽排序、OR、条件组或括号。规则如下：

- 默认创建两条条件，至少 2 条、最多 4 条；
- 相同 `kind + days` 不允许重复，避免同一观察窗口被无意配置两次；不同周期视为不同条件；
- 达到 4 条后禁用“添加条件”，并说明首版上限；
- 条件顺序只用于页面和报告定位，不改变 AND 的逻辑语义；
- 因子研究仍然逐个运行，用于决定每条条件的方向和区间，不把单因子结果当作最终策略。

输入错误在字段下方说明如何修正，不调用浏览器 `alert()`：

- 回看天数必须大于 0；
- 区间下限不能大于上限；
- 未知因子或预设策略由服务端拒绝；
- 因子数据不足产生的 `NaN` 不作为 0，而是不参与买入判断。

### 5.3 自动建立组合与归因对照

用户配置 N 个条件并点击“运行对照回测”后，后端固定生成 N+2 个变体：

```text
基准：基础 Buyer
单条件 1：buy.And{基础 Buyer, 条件 1}
……
单条件 N：buy.And{基础 Buyer, 条件 N}
组合增强：buy.And{基础 Buyer, 条件 1, …, 条件 N}
```

结果页主区域只突出“基准 / 组合增强”，各单条件变体放在“条件贡献”区域，优先比较：

- 基准、各单条件和组合的交易笔数及相对基准的信号保留率；
- 平均收益、胜率、盈亏比；
- 最大回撤及按年稳定性（后端已有数据时展示）。

页面不只突出胜率，也不把交易数减少造成的亏损额下降解释为因子有效。单条件变体只用于解释组合，不能被标记为最终推荐策略。

### 5.4 当前回测口径必须可见

MVP 不改变回测成交模型，因此运行按钮上方必须显示当前事实：

> 当前研究口径：使用当日日线生成信号，并按当日收盘价成交。若指标依赖完整收盘数据，结果可能偏乐观；本次结果不代表可实盘成交。

在后端支持“收盘后决策、下一可交易时点成交”之前，页面不得使用“无前视”“可实盘”等承诺性文案。

## 6. 视觉与内容方向

目标用户是熟悉 A 股策略、但不一定熟悉因子研究术语的个人研究者。页面的单一任务是“逐个理解指标，并把少量可解释条件安全地组合进旧策略”。

### 6.1 延续现有视觉语言

首版不重做整个实验室，继续使用现有浅灰背景、白色工作区和蓝色主操作。视觉重点放在一条有真实含义的“因子路径”：

```text
数值描述 → 历史验证 → 策略过滤
```

它既是页面导航线索，也是因子概念的持续解释，不使用无意义的步骤装饰。

颜色规则：

- 蓝色：当前选择和主操作；
- 中性灰：解释、单位、样本范围；
- 红涨绿跌：只用于收益和 A 股行情语义；
- 琥珀色：数据覆盖、成交口径和研究限制；
- 不用红绿单独表达“好/坏”，同时给出文字或符号。

字体继续使用系统中文字体和等宽数字字体，不新增在线字体依赖。图表与表单保持紧凑、可审计的研究工具风格，不使用交易终端式闪烁和营销化大数字。

### 6.2 状态要求

每个异步区域都必须有稳定尺寸，并覆盖：

- 初始引导；
- 加载中与可停止状态；
- 无有效样本；
- 部分股票加载失败；
- 分析失败及重试；
- 分析完成；
- 已加入策略条件但尚未补齐或回测。

按钮运行中保持尺寸不变并阻止重复提交。任务互斥返回时明确说明“已有回测或因子分析正在运行”，不显示原始 Go 错误。

### 6.3 MVP 控件归属

首版继续使用原生表单控件，避免为本地单页工具引入新的组件库，但必须明确行为归属：

| 能力 | MVP 选择 | 理由与约束 |
|---|---|---|
| Tab | 应用自有 Tab | 补齐 `tablist/tab/tabpanel`、方向键、选中状态和焦点样式 |
| 单选下拉 | 原生 `<select>` | 接受 Windows/浏览器拥有弹层外观；不承诺自定义弹层宽度和圆角 |
| 年份 | 原生数字输入 | 只输入年份，不新增日期选择器 |
| 表单校验 | 应用自有 | 表单使用 `novalidate`，字段错误用关联文本展示并聚焦首个错误 |
| 运行状态 | 应用自有状态区 | 提供 `aria-live` 文本，进度、停止、错误和重试不依赖颜色 |
| 滚动条 | 浏览器可见滚动条 | 不隐藏滚动条；表格自身横向滚动，不让表格高度约束配置表单 |

现有高级脚本 textarea、交易明细日期筛选和其他页面控件不在本 MVP 的修改范围内；实施时若触及它们，应另行补齐控件归属和一致性，而不是在本功能中顺手重写。

## 7. 数据契约

### 7.1 简单策略配置

新增独立的 Web 配置契约，不生成 Go 源码：

```json
{
  "version": 1,
  "name": "阴线收回MA5 + 动量与低波过滤",
  "basePresetId": "tail_pullback_ma5",
  "factorFilters": [
    {
      "kind": "momentum",
      "days": 20,
      "operator": "gte",
      "min": 0.05
    },
    {
      "kind": "volatility",
      "days": 20,
      "operator": "lte",
      "max": 0.03
    }
  ],
  "exit": {
    "holdingDays": 1,
    "takeProfit": null,
    "stopLoss": null
  },
  "run": {
    "startYear": 2022,
    "endYear": 2025,
    "sampleMode": "random",
    "sampleSize": 300
  }
}
```

约束：

- `basePresetId` 从后端显式注册表选择，不通过反射枚举所有 Buyer；
- `factorFilters` 必须有 2～4 项，按数组顺序生成归因变体，最终组合固定为 AND；
- 相同 `kind + days` 拒绝重复，不同周期允许并存；
- `version` 必填，后续升级时显式迁移；
- 服务端重新校验全部枚举、参数和范围，不能信任前端；
- 报告保存原始配置快照和实际构建出的 Buyer/Seller 名称。

### 7.2 API

在保留现有接口的前提下新增：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/strategy-presets` | 返回首版支持的基础策略及参数说明 |
| POST | `/api/strategy/run` | 校验配置、构建基准/单条件/组合增强变体并启动回测 |

继续复用：

- `GET /api/factors`：扩展展示元数据，保留现有字段；
- `POST /api/analyze`：运行单因子分析；
- `GET /api/analysis/latest`：读取分析结果；
- `GET /api/status`、`POST /api/stop`：共享单任务状态机；
- 原 `/api/run`：继续服务高级脚本模式。

简单模式和高级脚本模式必须复用同一条 `researchrun` 数据加载、覆盖率、深拷贝隔离、成本和报告链路。禁止为 Web 表单再复制一套回测循环。

### 7.3 报告补充字段

因子分析报告至少补充：

- `Coverage{Requested, Completed, Skipped, Failures}`；
- 每个因子的展示单位和解释快照；
- 实际样本池、年份、未来收益窗口；
- 无效值数量及原因分类能够获得时一并记录。

回测报告保存完整 `StrategySpec`，避免以后注册表默认参数变化后无法解释旧结果。

## 8. 后端构建边界

推荐新增显式注册表：

```text
StrategyPresetRegistry
  preset id → Builder(params) → core.Buyer

FactorRegistry
  kind → Builder(days) → core.Factor
```

`POST /api/strategy/run` 的构建流程：

```text
解析并校验 StrategySpec
        ↓
构建基础 Buyer
        ↓
逐项构建 Factor 与 A因子过滤
        ↓
生成“基准 / 各单条件 / 组合增强”N+2 个 core.Variant
        ↓
进入现有 researchrun + Report 流程
```

首版只增加新的配置与构建入口，不修改受保护的 `core.Buyer`、`core.Seller`、`Trade` 等核心接口。

## 9. 验收标准

1. 用户从启动 Lab 到完成一次“基准 vs 多条件组合增强”回测，全程不需要编辑 Go 代码。
2. 因子研究页默认先解释指标和五组表现，IC 统计位于可展开详情中。
3. 用户能明确区分因子数值、买入条件、因子过滤和卖出规则。
4. 首版允许 2～4 个因子条件且固定 AND，页面不出现权重、评分、TopN、OR 或组合调仓控件。
5. 简单模式生成的组合增强变体与手写 `buy.And{base, filter1, ..., filterN}` 行为对拍一致。
6. 因子数据不足、加载失败和覆盖率下降均可见，不静默当作 0 或完整样本。
7. 运行失败后保留所有表单值，并给出可操作的修正说明。
8. 任务进行中不能重复提交，可停止，刷新页面后能恢复当前任务状态。
9. 报告落盘包含完整配置快照，历史报告不依赖当前默认值解释。
10. 高级脚本模式及原有 API、报告不回归。
11. Tab、表单、按钮、进度和错误状态支持键盘操作、可见焦点及文本状态提示。
12. 桌面小屏和窄屏下表单可完整访问；表格允许明确的横向滚动，不截断关键值。

## 10. 建议实施切片

### Slice A：概念与目录

- 扩展因子目录元数据；

### Slice C：对照报告与稳健性

每个 Slice 都应独立可验证；在 Slice B 通过以前，不实现 TopN、权重评分或 OR/嵌套条件。

## 11. 后续决策点

以下问题不在 MVP 中猜测答案，后续需要单独设计：

1. TopN 是全股票池排名、基础 Buyer 候选内排名，还是目标持仓排名；
2. 加权/评分型多因子如何标准化、去极值、合成和版本化；
3. 收盘因子应在下一开盘、集合竞价还是尾盘快照成交；
4. 是否需要账户级组合、资金约束和调仓成本；
5. 策略配置是否需要命名保存、复制、版本历史和删除；
6. 因子阈值如何在训练期选择并冻结到样本外验证。
