# 多因子组合研究 v2 设计

> 日期：2026-09-18  
> 状态：设计完成，待上游 v1 达到准入条件后实施  
> 上游：`docs/superpowers/specs/2026-09-18-factor-validation-v1-design.md`  
> 范围：多因子合成、目标组合、可交易执行、样本外组合验证与归因  
> 本文只定义产品和技术契约，不代表相关能力已经实现

## 1. 背景与阶段定位

专业因子研究不能停在“某个因子的 IC 看起来不错”。单因子通过验证后，下一步应回答：

1. 多个因子是否提供互补信息，还是重复表达同一风险暴露；
2. 合成规则是否只使用当时可见的训练数据；
3. 预测分数如何转成有约束、可成交、可复现的目标持仓；
4. 成本、停牌、涨跌停、T+1、整手和现金约束后，收益还剩多少；
5. 样本外组合表现来自哪些因子、股票、行业和市场阶段；
6. 研究过程中试过多少模型和约束，最终结论是否存在选择偏差。

因此，v2 不是增加一个“综合得分”字段，而是建立从已验证证据到组合结果的第二条审计链：

```text
FactorValidation（上游证据）
  → ValidatedFactorRef（冻结引用）
  → FactorTransform（截面变换）
  → CompositeScoreModel（合成分数）
  → TargetPortfolioPolicy（目标权重）
  → PortfolioExecution（可交易执行）
  → PortfolioReport（净值、风险、归因）
  → PortfolioValidation（滚动样本外结论）
```

现有 Lab 的 1–4 个因子区间 AND 条件仍是可解释筛选器；它不等于多因子截面排序，也不承担组合资金、权重和成交语义。

## 2. 实施准入条件

v2 可以先完成设计和测试夹具，但业务实现必须等 v1 满足以下最小条件：

1. `FactorValidation` 能稳定引用候选 revision、因子实现版本和冻结研究协议；
2. 默认标签已经支持“`t` 日收盘形成信号，`t+1` 日开盘成交”；
3. 历史股票池、PIT、复权、可交易性和数据版本能生成机器可读质量结论；
4. 多周期 IC、HAC、换手和试验账本具备不可变结果；
5. 验证结论至少区分 `passed`、`failed`、`insufficient`、`error`；
6. `prospective`、`retrospective`、`exploratory` 证据等级不能被下游提升或覆盖。

若上述条件只部分实现，v2 只能以 `sandbox` 模式运行，结果必须标为探索性，不能产生“组合已验证”结论。

## 3. 目标与非目标

### 3.1 v2 目标

1. 模型只能引用冻结的因子验证结果；引用中固定候选 revision、实现版本、方向和证据等级。
2. 明确定义去极值、缺失处理、中性化、标准化和合成顺序，避免同一模型在不同运行中漂移。
3. 提供两个可审计基线：等权秩合成和仅使用训练窗的滚动 IC 权重；等权秩是默认基线。
4. 输出因子相关、覆盖重叠、边际 IC 和留一法结果，揭示冗余但不自动替用户删因子。
5. 将分数转换为 long-only 目标组合，支持 Top N、等权、单票上限、行业上限、换手上限和现金缓冲。
6. 新建独立组合执行引擎，支持次日开盘、卖出优先、T+1、停牌/涨跌停、整手、成本、滑点和未成交原因。
7. 同时输出毛收益与净收益、风险指标、成本拖累、现金、换手、行业暴露和贡献归因。
8. 冻结模型后进行非重叠滚动样本外验证；模型选择和超参数试验进入独立试验账本。
9. 保存不可变模型、运行和验证记录，使任一图表可追溯到输入、协议、代码和数据版本。
10. 在 Lab 增加一致的“组合研究”工作流，不改变现有因子、策略、对比、交易和候选页面语义。

### 3.2 v2 明确不做

- 不自动挖掘因子、自动搜索最优因子集合或遍历大量参数；
- 不实现黑盒机器学习、遗传算法、贝叶斯优化或端到端收益预测；
- 不把样本外测试窗用于选因子、调权重、调阈值或选择组合约束；
- 不把相关阈值、IC 门槛、持仓数或换手上限包装成普适金融规律；
- 不实现完整商业风险模型、协方差优化器、Barra 风格收益归因或冲击成本模型；
- 不实现真实账户、券商下单、订单路由或实盘风控；
- 不支持融券做空、多空资金账户、杠杆和衍生品；
- 不修改 `core.Backtest`、`Buyer`、`Seller` 等受保护核心契约来容纳组合语义；
- 不以单一“组合评分”替代完整证据、失败原因和限制说明。

## 4. 设计原则

### 4.1 证据等级只能保持或降级

组合证据等级等于所有输入因子、股票池、行情、执行和验证证据中的最低等级。任一输入是 `exploratory`，整个组合都不能标为 `retrospective` 或 `prospective`。

### 4.2 决策时点、观察时点、成交时点分离

- `signalAt`：`t` 日收盘后，因子值和模型分数可用；
- `decisionAt`：同一时点生成下一交易日目标组合；
- `eligibleFillAt`：最早 `t+1` 开盘；
- `markAt`：每日收盘按统一复权/估值口径计算净值；
- `evaluationAt`：只在完整观察窗口结束后评价结果。

任何同收盘成交只能作为兼容对照，并自动降级为探索性。

### 4.3 训练、冻结、测试严格隔离

等权秩模型没有拟合参数，但因子集合、方向、变换和约束仍必须在测试前冻结。滚动 IC 权重只能读取训练窗口；测试窗口只消费冻结后的规则和当时可用历史。

### 4.4 先有基线，再谈复杂度

每个复杂模型必须与以下基线比较：

- 单因子组合；
- 等权秩多因子；
- 不计成本的毛收益；
- 计入成本的净收益；
- 目标组合与实际成交组合。

若复杂度没有提供稳定、可解释的增量，就不晋级。

### 4.5 目标权重和实际持仓是两个事实

目标组合表达研究意图；实际持仓表达交易约束后的结果。报告不得用目标权重计算真实收益，也不得丢弃未成交、延迟成交和现金残留。

## 5. 领域模型

### 5.1 对象关系

```text
FactorModel
  ├─ ValidatedFactorRef[]
  ├─ TransformPipeline
  ├─ CombinationSpec
  ├─ PortfolioPolicy
  ├─ ExecutionSpec
  └─ ModelProvenance
        │
        ├─> PortfolioExperiment[]
        │      └─> PortfolioReport
        │
        └─> PortfolioValidation
               ├─ ValidationWindow[]
               ├─ GateResult[]
               └─ FinalVerdict
```

### 5.2 ValidatedFactorRef

每个引用至少包含：

| 字段 | 含义 |
|---|---|
| `candidateId` / `candidateRevision` | 不可变候选版本 |
| `validationId` | 上游验证记录 |
| `factorKind` / `factorDays` | 因子类型和参数实例 |
| `implementationVersion` | 计算语义版本 |
| `direction` | `higher_is_better` 或 `lower_is_better`，冻结后不可自动翻转 |
| `evidenceClass` | exploratory / retrospective / prospective |
| `primaryHorizon` | 上游主要预测周期 |
| `dataSnapshot` | 数据、股票池和质量快照引用 |

因子显示名称不能作为身份；身份由候选 revision、验证 ID、实例参数和实现版本共同确定。

### 5.3 FactorModel

`FactorModel` 是不可变配置快照，而不是可修改的“当前设置”。保存后修改任何因子、变换、权重、股票池、调仓或执行参数，都必须创建新 revision 和新的 `modelHash`。

建议逻辑字段：

```text
FactorModel
  modelId, revision, createdAt, createdBy
  researchQuestion, hypothesis
  validatedFactors[]
  transformPipeline
  combination
  portfolioPolicy
  execution
  benchmark
  evidenceClass
  modelHash
  codeVersion, dataSnapshot
```

### 5.4 PortfolioExperiment

每次运行都保存完整输入和结果引用：

- `experimentId`、`familyId`、`modelId/revision/hash`；
- 研究区间、训练区间、测试区间；
- 参数变体及变体来源；
- 运行状态、进度和错误；
- 数据快照、代码版本、随机种子（若未来使用随机算法）；
- 报告路径、报告 hash、证据等级；
- 是否计入试验次数以及计数理由。

失败、取消和无有效样本的运行同样进入账本，不得只保留漂亮结果。

## 6. 截面变换契约

对每个交易日的有效股票截面，按以下固定顺序处理：

```text
原始因子值
  → PIT/股票池/可交易性掩码
  → 缺失策略
  → 去极值
  → 可选风险中性化
  → 截面标准化
  → 方向统一
  → 合成输入
```

### 6.1 缺失策略

v2 支持：

- `exclude`：该因子缺失时，该股票不进入模型截面；默认且最容易审计；
- `cross_section_median`：仅用当日截面中位数填充，并额外输出缺失指示暴露；
- `renormalize_available`：按股票可用因子重新归一化权重，仅作为显式变体。

不得跨越未来日期填充，不得使用全样本均值，不得静默把 NaN 变成 0。

### 6.2 去极值

支持按当日截面分位数或 MAD 去极值。阈值必须配置化并写入模型 hash。若有效股票数不足，返回质量事件，不能沿用上一日边界。

### 6.3 中性化

v2 可选对行业哑变量和对数市值做当日截面回归，使用残差作为中性化值。要求：

- 行业和市值必须满足 `availableAt <= signalAt`；
- 输出回归样本数、秩、缺失率和残差覆盖；
- 矩阵奇异或覆盖不足时按协议 `fail` 或 `skip_with_degradation`；
- 同时保存原始与中性化对照，禁止只展示更漂亮的一版。

### 6.4 标准化和方向

默认使用当日截面百分位秩，并映射到 `[-1, 1]`；可选使用截面 z-score。这里的归一化只使用当日截面，不允许全样本 Min-Max。

方向先由上游验证冻结，再将“越好”统一为正方向。测试窗出现反向不允许自动翻转。

## 7. 多因子合成

### 7.1 等权秩基线

默认模型：

```text
score(i,t) = sum_j w_j * transformedFactor(i,t,j)
w_j = 1 / factorCount
```

每个因子的有效方向、变换和覆盖单独报告。若选择 `renormalize_available`，必须输出每日实际权重分布和由缺失导致的漂移。

### 7.2 滚动 IC 权重

可选模型只允许使用 `t` 之前的训练数据：

1. 在固定滚动训练窗计算每个因子的主周期 IC 均值或风险调整后 IC；
2. 对估计值做显式收缩，限制单因子绝对权重；
3. 根据冻结方向处理符号，不因短期反向而偷偷改方向；
4. 归一化后用于下一个重平衡周期；
5. 保存每次权重形成所用的起止日期、样本数和数据 hash。

训练数据不足时退回等权还是保持现金，必须由协议预先选择；默认退回等权并标记 `fallback`，不能临时择优。

### 7.3 冗余诊断

报告至少包含：

- 因子两两日截面 Spearman 相关的时间均值、分位数和有效日数；
- 有效股票覆盖的交集、并集和重叠比例；
- 单因子 IC 与合成分数 IC；
- 控制其他因子后的边际/残差 IC；
- leave-one-factor-out 对样本外 IC、收益、换手和回撤的变化；
- 因子在滚动权重中的稳定度和触顶次数。

相关阈值只用于提示，不自动删除因子。删除或合并因子必须形成新模型 revision，并进入试验账本。

## 8. 从分数到目标组合

### 8.1 v2 组合范围

- A 股 long-only；
- 按日或按周重平衡；
- 从当日有效股票池按合成分数选 Top N 或最高分位；
- v2 正式基线使用等权目标；分数比例权重留待后续版本；
- 未选中股票目标权重为 0；
- 允许配置现金缓冲。

### 8.2 约束顺序

```text
候选排名
  → Top N / top quantile
  → 初始等权
  → 单票上限
  → 行业上限
  → 可交易性预检查
  → 换手预算
  → 整手与现金可行化
  → 目标权重与目标股数
```

每一步必须输出调整前后差异和原因。约束冲突时按冻结优先级求解；无法得到最小持仓数或权重和时，返回 `insufficient`，不能静默放宽约束。

### 8.3 换手约束

换手上限用于限制目标组合变化，不保证实际成交换手恰好相等。报告同时展示：

- 无换手约束的理想目标；
- 约束后的目标；
- 实际成交后的持仓；
- 因不可交易和整手造成的额外偏离。

## 9. 组合执行与会计契约

### 9.1 独立引擎

新增 `internal/portfolioresearch`（最终目录以实施时仓库结构为准），不扩张 `core.Backtest`。原因是现有引擎以单股票 Buyer/Seller 交易为中心，不能表达统一现金账户、跨股票卖出释放资金、目标权重和组合级约束。

### 9.2 每个交易日的处理顺序

1. 读取前一收盘后生成的目标组合；
2. 根据停牌、涨跌停、上市状态和 T+1 规则确定可成交集合；
3. 执行可成交卖单，扣除费用并释放现金；
4. 按冻结优先规则分配可用现金执行买单；
5. 按整手规则向下取整，不允许负现金；
6. 保存每笔成交、拒绝、部分成交和未成交原因；
7. 收盘按持仓、现金和公司行为计算净值；
8. 对账 `期初资产 + 当日损益 - 费用 = 期末资产`。

同一日的信号不能影响该日开盘成交。若数据不足以判断涨跌停或停牌，按协议 fail closed，并降低证据等级。

### 9.3 T+1 和不可交易持仓

- 当日买入股票当日不可卖出；
- 停牌或卖出受限持仓继续保留并估值；
- 买入受限股票不使用未来价格补成交；
- 目标变更后未成交订单是否跨日保留必须配置；v2 默认不保留，下一信号日重新生成目标；
- 每个未成交原因使用稳定枚举，并进入报告。

### 9.4 成本与滑点

费用模型引用现有可复用配置，但组合引擎自行记账。至少区分佣金、印花税、过户费和滑点；所有参数进入模型 hash。

v2 使用显式、可配置的基础滑点，不宣称已建模市场冲击或容量。成交金额占市场成交额的比例只作为容量告警，不调整价格时必须明确标为未建模。

### 9.5 公司行为和基准

收益和估值必须统一采用已确认的复权/公司行为口径。若分红、拆并股和退市处理缺乏可靠数据，报告必须产生质量事件。

基准需绑定稳定标识、成分/价格来源和版本；基准缺失不阻止绝对收益报告，但阻止信息比率和超额归因通过门禁。

## 10. 报告与归因

### 10.1 组合报告

同时提供毛值和净值：

- 累计收益、年化收益、年化波动、Sharpe、Sortino；
- 最大回撤、回撤持续期、Calmar；
- 相对基准收益、跟踪误差、信息比率；
- 日/年换手、成本拖累、现金比例、持仓数；
- 目标与实际权重偏离、未成交数和原因；
- 行业、市值和单票集中度；
- 年度、市场阶段和滚动窗口稳定性。

所有年化指标必须保存交易日尺度、无风险利率和缺失处理口径。

### 10.2 预测归因

回答“分数为什么有效”：

- 单因子 IC、合成分数 IC、边际 IC；
- 因子间相关和覆盖；
- 每日/每窗实际合成权重；
- leave-one-factor-out 增量；
- 不同市场阶段的方向和稳定性。

### 10.3 组合归因

回答“收益从哪里来”：

- 股票贡献、行业贡献、现金贡献和成本拖累；
- 信号选择收益与执行偏离损失；
- 目标权重、实际权重和偏离时间序列；
- 单因子组合与合成组合的增量比较。

v2 的归因是统计分解，不是因果证明，也不是完整风险模型归因。页面和导出必须显示这一限制。

## 11. 样本外组合验证

### 11.1 窗口模型

采用非重叠外层测试窗：

```text
训练窗 → 冻结权重/规则 → 测试窗 A
滚动训练窗 → 冻结权重/规则 → 测试窗 B
...
```

因子集合、组合规则和门禁在验证开始前冻结。若研究者根据测试窗结果修改模型，必须创建新 revision 和新试验族；旧测试窗从此视为已见数据。

### 11.2 不在 v2 内自动调参

v2 只执行预先声明的参数。若未来需要在训练期选择超参数，必须增加内层 walk-forward，并保持外层测试窗完全隔离；在该能力实现前，不允许从多个测试结果中自动挑最好者。

### 11.3 门禁

门禁均为协议字段，不是硬编码金融真理。建议模板可包含：

- 有效测试窗数和有效交易日下限；
- 净收益、最大回撤和成本拖累边界；
- 相对基准信息比率或超额收益稳定性；
- 换手、现金残留、未成交和集中度边界；
- 多数窗口方向一致性；
- 相对等权秩基线的增量；
- 数据质量和证据等级要求。

最终状态仍使用 `passed | failed | insufficient | error`。其中 `passed` 只表示通过冻结协议，不表示未来盈利保证。

```text
output/portfolio/<experiment-id>/nav.csv
output/portfolio/<experiment-id>/orders.csv
output/portfolio/<experiment-id>/trades.csv
output/portfolio/<experiment-id>/holdings.csv
```

正式记录使用服务端 ID、规范化 JSON hash、临时文件 + rename、安全根目录检查和只追加 revision。大型时序产物可分文件保存，但清单和 hash 必须进入主报告。

### 12.2 API 资源

- `/api/factor-models`：创建 revision、列表、详情；
- `/api/portfolio-experiments`：创建、列表、详情和产物索引；
- `/api/portfolio-validations`：创建、列表、详情；
- `/api/portfolio-runs/*`：启动、停止和读取任务状态；
- `/api/status`：继续作为全局长任务进度契约。

创建运行是长任务提交，成功只表示任务已被服务端接受；最终结果以持久化状态为准。所有列表默认服务端分页，过滤、排序和页码可恢复。

### 12.3 兼容性

- 不改变旧因子分析、候选和策略回测 JSON；
- 新报告独立版本化，不把组合字段塞进单因子 `AnalysisReport`；
- 删除因子模型不删除其历史运行；v2 优先采用归档而非硬删除；
- 旧记录缺少新字段时显示 `unknown`，不能补造默认事实。

## 13. Lab 产品与交互设计

### 13.1 页面定位

在现有五个页签后增加 `06 组合研究`。页面只做一件事：把已有验证证据组装成冻结模型，并检查其样本外组合表现。

不改变现有视觉身份：继续使用系统字体、深海军蓝头部、钴蓝交互色、中性研究面板；红绿只表达 A 股收益语义，琥珀只用于警告和降级。

### 13.2 信息架构

```text
组合研究
  ├─ 模型列表：状态、revision、证据等级、因子数、最近验证
  ├─ 模型编辑：输入证据、变换、合成、组合、执行、门禁
  ├─ 运行详情：目标/实际、净值、风险、执行质量
  ├─ 归因详情：因子、股票、行业、成本、偏离
  └─ 验证详情：窗口、门禁、结论、限制、产物
```

模型创建完成后返回模型列表并聚焦新行；编辑产生新 revision，不原地覆盖。归档属于可恢复低风险操作，使用明确反馈；运行和验证使用服务端确认、持久进度和失败恢复。

### 13.3 视觉签名：证据脊柱

页面中心使用一条紧凑的“证据脊柱”，按真实数据流连接：

```text
验证因子 → 变换 → 合成分数 → 目标权重 → 实际持仓 → 样本外结论
```

每一节点显示状态、版本和降级原因；点击后定位到对应配置或报告。它编码审计关系，不做装饰动画，也不代替详细表格。

### 13.4 关键交互契约

- 选择器继续使用原生 `<select>`，接受平台弹层外观，不伪装成可完全定制控件；
- 表格排序触发器使用按钮并维护 `aria-sort`；
- 长任务复用全局状态栏，未知总量显示不确定进度，已知后才显示百分比；
- 后台刷新保留旧内容并标注 stale，不闪白、不允许旧请求覆盖新选择；
- URL 保存 `tab`、`model`、`revision`、`run`、分页和过滤状态；
- 窄屏保留关键 ID、状态和操作；比较型表格横向滚动，不静默隐藏列；
- 每个详情状态包含 loading、empty、no-results、running、partial、stale、error、done；
- 错误显示在所属区域并提供重试，用户输入在服务端错误后保留；
- 焦点在创建、保存、归档、运行完成和错误恢复后移动到可解释位置；
- 页面不展示一个脱离证据的“魔法总分”。

### 13.5 设计上下文维护

实施 UI 前：

1. 从正式业务设计提炼并创建 `UX-CONTRACT.md`，只记录 UI 后果和来源，不复制业务规则；
2. 更新 `DESIGN.md` 的页面架构、组件合同、状态和视觉签名；
3. 保持现有 token 所有权，不新增第二套颜色、字体、阴影和状态词汇；
4. 浏览器验证成功、失败、键盘、窄屏、200% 缩放、慢请求和 stale 请求；
5. 严格 UI 审计、可访问性和反模式检查必须作为实施完成门槛。

## 14. 失败、降级与恢复

| 情况 | 处理 |
|---|---|
| 输入验证已归档或 hash 不匹配 | 阻止新运行，历史结果保持可读 |
| 输入中存在 exploratory 因子 | 允许 sandbox，组合证据降级 |
| 当日有效股票不足 | 当日跳过并记录；超出协议容忍度则 insufficient |
| 中性化矩阵失败 | 按冻结策略 fail 或降级跳过 |
| 训练窗不足 | 按冻结 fallback；不得运行后选择 |
| 行情/股票池/PIT 数据缺失 | fail closed，保存质量事件 |
| 运行取消 | 保存 cancelled 和已有诊断，不发布正式报告 |
| 产物写入失败 | error；不留下看似完成的主记录 |
| 浏览器断开 | 服务端任务继续；重连后从状态和持久记录恢复 |
| 实际持仓无法满足约束 | 保留可成交持仓和现金，报告偏离；严重时 insufficient |

## 15. 安全、性能与可复现性

- 所有文件 ID、路径和下载名由服务端验证，禁止目录穿越；
- API 对日期、数量、权重、阈值和数组长度设置可配置资源上限；
- 因子矩阵按日期流式处理，避免一次性加载全部股票×日期×因子；
- 运行缓存键包含模型 hash、数据快照、代码版本和区间；
- 相同输入应生成相同模型 hash 和统计结果；
- 报告记录软件版本、数据版本、时区、交易日历和数值口径；
- 导出不包含本地绝对路径、密钥或无关环境信息。

## 16. 验收标准

1. 未通过 v1 准入条件的模型不能产生正式组合验证结论。
2. 任一组合结果可以追溯到固定因子 validation、candidate revision、实现版本、数据和代码版本。
3. 截面变换只使用当日可见数据，且顺序、阈值和失败策略进入模型 hash。
4. 等权秩合成有手工小样本金标准测试；滚动 IC 权重不能读取测试窗。
5. 因子冗余报告包含相关、覆盖、边际 IC 和留一法，不自动删除因子。
6. 目标组合约束步骤可解释，约束冲突不会静默放宽。
7. 执行引擎遵守次日开盘、卖出优先、T+1、整手、现金和不可交易规则。
8. 每日会计恒等式通过；订单、成交、持仓、现金和净值可以逐日对账。
9. 报告同时展示毛/净收益、成本拖累、目标/实际偏离和未成交原因。
10. 样本外测试窗不参与选因子、调权重或门禁；修改后必须产生新 revision 和试验记录。
11. `passed`、`failed`、`insufficient`、`error` 由后端按冻结门禁生成。
12. 组合证据等级不会高于最弱输入证据。
13. 新 API 不破坏现有因子分析、候选、策略和回测接口。
14. 组合研究页覆盖完整异步状态、键盘、窄屏、URL 恢复和 stale 请求保护。
15. `DESIGN.md`、`UX-CONTRACT.md`、正式设计、API 和页面术语一致。
16. 相关 Go 测试、静态检查、UI 严格审计和真实浏览器关键路径通过。

## 17. 后续阶段

v2 完成并积累稳定证据后，再单独评审：

- 行业/风格风险预算和协方差优化；
- 分数比例或风险平价权重；
- 容量、冲击成本和参与率模型；
- 内层 walk-forward 超参数选择；
- 组合层 PBO/Deflated Sharpe 等选择偏差诊断；
- 纸面交易和真实前瞻观察；
- 经账户、风控、恢复和审计设计后的实盘执行。

这些能力不得作为 v2 实施中的顺手扩张。
