# 候选因子独立页面（第 5 个 Tab）设计

> 日期：2026-09-17
> 状态：已实施并验证（2026-09-17）
> 前置：`2026-09-17-factor-candidate-library-design.md`（候选因子库，已实施并验证）

## 1. 背景与目标

候选因子库（保存表单 + 列表卡）目前内嵌在“因子研究”tab 底部，页面偏长且候选管理与因子研究混在一起。目标：把候选管理拆为独立页面，便于日常查阅、修订与复用。

用户已确认的决策：

1. **形态**：新增第 5 个顶级 tab（沿用现有单页 tab 模式），不做独立 URL 页面。
2. **保存表单归属**：“保存为候选因子”表单留在因子研究 tab 的分析结果区（强依赖当前分析上下文）；保存成功后提供“查看候选 →”跳转。
3. **功能范围**：候选列表原样迁移，交互不变；不做状态筛选 chips、不做懒加载、不拆 JS 模块文件。

## 2. 设计

### 2.1 导航

- 新增第 5 个 tab 按钮：`05 候选因子`，`data-tab="5"`，slug `candidates`，副标题体现“证据 · 修订 · 复用”语义。
- `TAB_SLUG` 增加 `5: 'candidates'`，`TAB_NUM` 增加 `candidates: 5`；`switchTab(5)` 产生 `?tab=candidates`。
- 键盘左右循环基于 `[role=tab]` 集合，自动包含新按钮，无需额外逻辑。

### 2.2 布局

- 新 tab5 panel：将现有 `#candidateSection` 卡片整体迁入（标题“我的候选因子”、“查看归档/刷新”、`#candLoadErr` 警示条、候选表格）。DOM 结构、类名、元素 ID 全部不变。
- 证据 dialog（`#candEvDlg`）与编辑 dialog（`#candEditDlg`）为顶层元素，位置不动。
- 因子研究 tab：移除底部 `#candidateSection` 卡；`#candidateForm` 保持在分析结果区内不变。

### 2.3 JS 行为

- 候选 JS 模块（`loadCandidates`/`renderCandidates`/证据/编辑/归档/恢复/加入策略）零修改——全部通过不变的元素 ID 操作。
- `loadCandidates()` 维持页面加载即拉取（本地数据量小，不做按 tab 懒加载）。
- `joinCandidateToStrategy` 现有 `switchTab(1)` 跨 tab 行为保持。
- 保存成功提示追加“查看候选 →”跳转（`switchTab(5)`）。

### 2.4 错误处理

- `#candLoadErr` 随卡片迁移，加载失败可重试逻辑不变。
- HTTP API 层零改动。

## 3. 测试与验收

- Go 测试：无 API 变化，现有全部测试应保持通过。
- `node --check`：JS 语法验证。
- 浏览器验收清单：
  1. `?tab=candidates` 直接打开显示候选列表；无参默认仍为因子研究。
  2. 因子研究页保存候选成功后出现“查看候选 →”，点击切到候选页且列表含新候选。
  3. 候选页“加入策略”切到策略 tab，条件卡带“尚未回测”chip。
  4. 证据/编辑/归档/恢复/查看归档在新 tab 全部可用。
  5. 键盘 Tab/方向键可循环到新 tab 按钮。

## 4. 范围外

- 状态筛选 chips、概览统计、懒加载、JS 模块文件拆分：均不做。
- 后端存储、API 合同：不动。
