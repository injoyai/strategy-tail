# 回测逐日回放需求

日期：2026-10-18（Asia/Shanghai）。
状态：首版业务范围已由用户确认并实现；验证结果及未覆盖范围见[审核验收报告](../reviews/2026-10-19-replay-practice-acceptance.md)。

## 1. 目标与适用范围

让用户按交易日观察策略执行过程：先看账户收益和持仓如何变化，再进入个股查看走势、成交位置和触发原因，以理解收益来源及买卖行为。

首版面向现有 Lab 账户回测，沿用自由搭建与因子组合的运行流程。回测完成后生成可回放结果；回放中的“实时更新”指所有视图随回放日期同步更新，不指实时行情或计算过程中推送账户状态。

现有回测结果、交易明细及报告历史继续承担完整结果浏览；回放是观察同一次运行过程的方式，不产生另一个账户，也不重新执行策略。

## 2. 已确认的首版决策

| 项目 | 已确认行为 |
| --- | --- |
| 观察路径 | 从账户变化进入持仓、个股和成交详情 |
| 运行与播放 | 先完成回测，再播放结果 |
| 时间单位 | 一个交易日一帧，展示当天收盘后的账户状态 |
| 播放控制 | 播放／暂停、上一交易日／下一交易日、拖动日期、慢／中／快三档 |
| 成交暂停 | 提供“遇到买卖自动暂停”开关，默认关闭 |
| 查看详情 | 点击持仓或成交时自动暂停，手动点击播放才继续 |
| 未来信息 | 隐藏当前回放日期之后的行情、成交、卖点、最终收益及曲线 |
| 账户数量 | 一次观察一个策略账户，保留上证指数对照 |
| 切换策略 | 保留当前回放日期，同步切换账户、持仓、成交和图表 |
| 成交解释 | 展示实际触发的规则、参数及命中分支 |
| 解释深度 | 不展示全部指标实际值，不解释满足信号但未成交的原因 |
| 人工干预 | 不支持回放中手动买卖或修改策略参数 |

## 3. 用户流程与播放行为

1. 用户沿用现有配置运行回测，等待计算和报告保存完成。
2. 从有完整回放数据的报告进入回放，选择该报告中的策略账户。
3. 播放或逐日步进，账户摘要、收益图、持仓与当天成交同步更新。
4. 点击持仓或成交，暂停在当前日期，查看个股图及已经发生的成交原因。
5. 手动恢复播放，或回退、拖动日期，反复检查同一段过程。
6. 到达最后一个交易日后停止，终点账户与正式结果一致；用户仍可回退查看。

补充交互约定：

- 首次进入报告回放时停在首个交易日，默认暂停；首帧已包含该日发生的成交及收盘估值。
- 按本次回测交易日历推进，周末、节假日不产生空白帧；无成交的交易日仍推进并更新持仓估值。
- 拖动日期或手动步进时暂停，不能由旧播放计时继续推进；首日不能再后退，末日不能再前进。
- 三档速度只影响观看间隔，不影响成交或收益；具体间隔在实施设计中确定。
- 开启成交自动暂停后，播放推进到有实际买卖的日期，展示该日完整收盘状态和当天所有成交后暂停；同一天不拆成多帧。期末估值不触发成交暂停。
- 一只股票已卖出时，当天成交仍可打开个股详情，不能要求该股票仍在当前持仓中。
- 切换策略时暂停并保留同一日期；不继续显示上一账户的成交原因或详情。切换到另一份报告时从新报告首日暂停开始。
- 离开回放区域时暂停；加载、错误或无数据期间不能后台推进日期，也不能让旧请求覆盖新日期、新策略或新报告。

## 4. 同步展示内容

### 4.1 账户摘要与收益图

账户摘要展示当前日期、总资产、可用现金、持仓市值、仓位比例、当日盈亏和累计收益率。数值携带金额或百分比单位，收益采用 A 股红涨绿跌语义，并保留正负号，不能只依赖颜色。

收益图展示截至当前日期的策略累计收益率与同期上证指数收益率，明确当前位置。当前日期之后的数值不得出现在曲线、提示框或详情中；如保留完整日期刻度，未来日期只可显示为空白。

回放入口附近不得用完整回测的最终统计泄露未来结果。退出回放后可继续使用现有完整结果页面；首版不提供提前显示未来信息的开关。

### 4.2 当日持仓

每只持仓展示股票标识、持仓数量、买入日期、成本、当前估值价、市值、浮动盈亏金额与浮动收益率。股票名称可在已有可靠名称数据时显示，不应因名称缺失阻止查看。

成本需要区分含买入费用的持仓总成本与成本单价；不能把日线原始买入价直接当作完整成本。已卖出的仓位不再进入收盘持仓；当日卖出后重新买入同一股票时，显示新仓位，保留当天两笔成交。

空仓时显示空仓状态、现金和账户收益，不视为数据加载失败。

### 4.3 当天成交

展示当前交易日全部实际买入与卖出：股票、方向、实际成交时间、实际成交价、数量、费用及触发原因。成交按实际执行顺序展示，同日多笔成交不能丢失或相互覆盖。

没有成交时明确显示“当日无成交”。首版不展示未成交信号列表，不把触发信号等同于实际成交。

### 4.4 个股图表

从持仓或成交进入同一套个股详情，展示截至当前日期的日 K、成交量、MACD 和已经发生的买卖点。可使用回测开始前的行情作为指标预热与观察背景；不得使用回放日期之后的行情计算当前指标。

买卖点与实际成交事件对应，支持一只股票多次买卖及同日卖出再买入；详情显示准确成交时间、价格和数量。日 K 只定位到交易日，不声称呈现分钟内的账户变化。原始行情价与含滑点成交价如有差异，必须区分。

## 5. 成交触发原因

原因记录本次实际执行中导致成交的买入规则、策略卖出信号或独立风控，包含规则名称、当次有效参数以及条件组中的命中路径，使用该次回测的策略快照，不读取策略库后来修改的规则。

示例：

```text
买入条件 → 全部满足 → 价格范围、MACD 连涨 3～5 天
策略卖出信号 → 任一满足 → MACD 卖出条件
独立风控 → 固定止损 5%
```

示例用于说明解释粒度，不要求策略默认包含这些条件。

原因必须满足：

- 来自原策略求值过程，不在成交后或播放时重新执行条件以推断原因。
- 保留原求值顺序、短路规则及风控优先级；不能为了获取原因额外执行本来不会执行的分支。
- AND 成交路径反映实际满足的条件；OR 路径记录实际导致成立的分支，不能声称其余未执行分支均不成立。
- 首版只展示命中规则和参数，不要求逐项记录或展示指标实际值，也不展示整棵树的失败诊断。
- 显式基准买入应说明其基准规则来源；期末持有只表示尚未卖出，不能虚构卖出触发原因。
- 不透明的预设或旧脚本不得伪造内部命中路径。实施设计需盘点可记录的粒度并明确能力边界；不能以整个策略名称冒充已记录内部条件路径。

## 6. 账户与时间口径

首版沿用现有账户执行假设，不借回放功能改变策略、成交时点、T+1、费用、买入优先级及资金约束：已有持仓盘中卖出，当日收盘买入，收盘估值；跨年延续资金和持仓。

| 指标 | 口径 |
| --- | --- |
| 持仓市值 | 当前各持仓估值价 × 数量后求和 |
| 总资产 | 现金 + 持仓市值 |
| 累计收益率 | （总资产 ÷ 初始资金 − 1）× 100% |
| 当日盈亏 | 当日总资产 − 上一交易日总资产；首日为当日总资产 − 初始资金 |
| 仓位比例 | 持仓市值 ÷ 总资产 × 100% |
| 持仓浮动盈亏 | 当前持仓市值 − 该持仓含买入费用的成本 |
| 持仓浮动收益率 | 持仓浮动盈亏 ÷ 该持仓含买入费用的成本 × 100% |
| 上证指数收益率 | 沿用报告中的同期价格收益率，以本次首个交易日收盘为基准，不扣交易成本 |

费用与滑点沿用现有成本模型，不重复计费；持仓估值不预扣尚未发生的卖出费用。金额、估值及原因来自本次保存的执行结果，前端不能通过交易收益相加或复利推算账户；若分母无效，不显示伪造的零收益或无穷百分比。

买入之后、真正卖出之前，不得显示该笔交易未来的卖出时间、卖出原因及最终盈亏。已完成交易的结果只在实际卖出日及之后可见。

期末 `Virtual` 只用于原报告的未平仓估值兼容；回放末日仍显示持仓，不因该记录改变现金或持仓，不生成卖出事件、卖点或卖出费用。

## 7. 数据保存、异常与兼容

- 每日账户、每日持仓、实际成交与触发原因须属于同一次报告，保存后重新打开仍可回放；播放、回退与调速不重新执行策略。
- 修改策略库或更新行情不能重新解释该报告的金额、成交与原因。图表行情的保存或读取一致性方案在实施文档确定；不得无提示地把后来的不同价格当作该次成交依据。
- 缺持仓当日日线时，沿用现有上一价格估值，并在对应日期、股票处披露价格日期；不能把沿用价格显示为当天新价格。
- 缺分钟行情而使用日线收盘判断卖出时，在对应日期或成交处披露降级；不能把它显示为有分钟证据的成交。
- 基准缺失、加载失败、报告损坏或回放数据不完整时，提供明确状态与必要的重试入口，保持已选报告和策略；不得悄悄生成替代收益或拼接不同运行的数据。
- 没有回放数据的旧报告继续支持原结果浏览，提示重新运行以获取完整回放。不得自动修改旧报告、补造每日持仓或触发原因，也不得把“未记录”显示为“没有持仓／没有成交”。
- 旧逐股模式、旧脚本 API、既有 CSV／HTML 导出和组合研究不因本功能改变原有执行与统计口径；首版不承诺为这些路径补齐完整回放能力。

## 8. 界面与可用性

复用项目现有布局、组件及图表能力，保持紧凑的工具界面。页面名称只出现一次，主要控制、当前日期与核心内容优先进入首屏，不增加装饰横幅或无用途统计卡片。

桌面与窄屏均能操作播放控制、选择策略、查看持仓和成交。窄屏可将图表与详情改为纵向排列，表格可在自身容器内滚动，不能让整个页面溢出或隐藏主要操作。

播放控制、日期选择和成交详情应可通过键盘操作，并有明确焦点、标签和状态。尊重减少动态效果偏好，功能不依赖图表过渡动画；回放推进与装饰动画分开处理。

## 9. 首版验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| R01 | 首次进入、连续播放及终点 | 从首日暂停开始，每次推进一个交易日，到末日停止；所有区域日期一致 |
| R02 | 暂停、步进、拖动与速度 | 暂停后不继续推进；手动定位后日期稳定；速度不改变任何金额或成交 |
| R03 | 历史日期可见性 | 回退后图表、标记、提示框、详情均不暴露未来卖点、成交原因或最终收益 |
| R04 | 状态可重复 | 前进、回退再前进到同一天，账户、持仓、成交、原因及图表一致，不重新求值策略 |
| R05 | 无成交与空仓 | 无成交日仍更新估值；空仓能展示现金与收益，不出现错误或残留持仓 |
| R06 | 买卖与资金约束 | 覆盖买入、卖出、T+1、同日卖出再买入、跨年持仓；回放与原执行一致 |
| R07 | 原因及分支 | 覆盖 AND、OR、嵌套条件及风控优先；展示真实命中路径，不额外求值或把未执行分支标为失败 |
| R08 | 自动暂停 | 开关默认关闭；开启后在成交日完整展示当天结果后暂停；估值事件不触发；手动恢复能继续 |
| R09 | 查看详情 | 点击持仓或成交即暂停；已卖出股票可查看；打开详情不会清除当天其他成交 |
| R10 | 策略及报告切换 | 策略切换保留日期并暂停，报告切换重置；无旧账户内容或异步旧响应混入 |
| R11 | 期末未平仓 | 最后一天仍为持仓，没有虚构卖点、卖出原因或卖出费用；终点总资产与报告一致 |
| R12 | 数据降级与错误 | 缺日线、缺分钟线及读取错误有对应提示；不显示伪造行情、账户或原因 |
| R13 | 保存与兼容 | 报告重开可回放；旧报告可继续浏览并明确能力缺失；修改策略不改变旧原因 |
| R14 | 展示与可访问性 | 桌面、窄屏及键盘操作可用，无重复标题、页面溢出、不可见主操作或仅靠颜色传达的收益 |
| R15 | 执行等价 | 同输入启用过程记录前后，成交、数量、费用及每日账户结果保持一致 |

## 10. 首版不包含

- 计算过程中展示或推送逐日账户状态。
- 分钟级或逐笔账户动画，以及实时行情接入。
- 手动买卖、修改参数继续运行或人工干预结果分支。
- 同屏比较多个策略账户的持仓与成交。
- 全部指标实际值、未成交信号、资金不足等未成交原因的诊断。
- 增加分红现金流、涨跌停排队、成交容量等新的交易模型。
- 重构全部回测执行器或升级图表及前端依赖。

## 11. 与实施文档的分工

建议顺序为：本需求文档 → [精简实施文档](../plans/2026-10-18-backtest-replay.md) → 编码与验证。需求定义行为与验收；实施文档定义如何在现有代码上落地，不重复进行业务选型。

编码前实施文档需解决：

1. 每日持仓、成交与原因的数据合同、保存位置、可用性识别及旧报告兼容。
2. 不改变 Buyer／Seller 求值次数、短路顺序和执行结果的原因采集方式，以及不透明预设的能力边界。
3. 个股行情与指标来源、预热范围及报告重开后的图表一致性处理。
4. 回放入口、统一日期状态、计时与请求失效处理、现有组件复用和窄屏布局。
5. 受影响调用方、报告读取与删除、导出兼容、测试夹具、任务拆分及各阶段验证。
6. 代表性长区间／多股票报告的数据量、加载与播放性能验证方法，不先引入未经需要证实的新架构。

本需求确认不构成对受保护核心结构格式变更的授权。优先在 Lab 现有边界内扩展；如确需修改受保护类型，按 [PROJECT_RULES.md](../../PROJECT_RULES.md) 先说明具体变更及理由并单独确认。
