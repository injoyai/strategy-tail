# 中期动量低波动策略

这是一份可以在 Lab「回测配置 → 自由搭建」中保存、编辑和回测的 A 股多因子研究基线。配置文件为 [`momentum_low_volatility.json`](../../strategies/configs/momentum_low_volatility.json)，使用现有因子和风控组件，无新增依赖、公共接口或公式。

“成熟”指规则明确、时点清楚、成本和资金约束可追溯；本策略尚无真实行情样本外收益证据，不能标记为已验证有效。下列阈值是本项目的初始研究假设，不是参考项目的推荐参数。

## 参考项目与适配边界

- [Microsoft Qlib：Portfolio Strategy](https://qlib.readthedocs.io/en/latest/component/strategy.html) 将预测信号、持仓选择和交易执行分开，并展示扣费前后表现。其 TopkDropout 通过持仓数量和每次替换数量约束换手。本配置借鉴分层思路；自由搭建器执行的是逐票阈值筛选，不实现 Qlib 的横截面排名、TopK 或 Drop 换仓。
- [QuantConnect LEAN：Risk Management](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/risk-management/key-concepts) 把风险控制作为独立模型。本配置沿用仓库的独立 `Seller` 风控，风险触发优先于趋势退出。
- 许可证核对：[Qlib MIT](https://github.com/microsoft/qlib/blob/main/LICENSE)、[LEAN Apache-2.0](https://github.com/QuantConnect/Lean/blob/master/LICENSE)。这里只借鉴设计方法，没有复制外部源码或收益结果。

## 买入规则

所有条件同时满足才产生买入信号，最少需要包含当日在内的 127 根日线。

| 条件 | 固定初值 | 作用 |
|---|---|---|
| 收盘价格 | 3～100 元 | 限制价格范围，不是预测因子 |
| 当日涨停过滤 | 使用已有板块阈值组件 | 过滤组件判定的涨停日，不代表具备排队成交模拟 |
| 跳月动量 | `C[t-21] / C[t-126] - 1 ≥ 0.05` | 看中期表现，避开最近一个月 |
| 日收益波动 | 最近 60 个日收益的总体标准差 ≤ 0.025 | 限制单票波动；2.5% 是日频标准差，未经年化 |
| 趋势位置 | `0 ≤ C[t] / MA120[t] - 1 ≤ 0.25` | 长期趋势向上，同时限制追高 |
| Amihud 非流动性 | 最近 20 日平均 `abs(r) / 成交额（元） × 1e8 ≤ 0.02` | 限制单位成交额对应的价格波动；它不是成交额下限或容量保证 |

因子都使用 `factorVersion: 1` 冻结当前实现。缺少必要历史、价格或成交额时按现有因子无效值规则拒绝买入。没有使用历史流通股本或财务快照，避免把当前市值或估值误当成过去可得信息。上述条件不包含历史 ST、退市状态或行业约束。

## 卖出与资金规则

以下任一条件触发即提出卖出，先求值独立风控，再求值趋势信号：

1. 收盘价相对原始买入价下跌达到 8%。
2. 从买入以来最高收盘价回撤达到 12%。
3. 买入之后经过 20 个交易日，不含买入当天。
4. 最新收盘价低于 60 日均线至少 2%，为趋势退出留出缓冲。

风控是触发条件，不能保证实际亏损限制在该比例以内；费用、跳空和不可成交均会造成偏离。配置中的风控参数 `pct: 8`、`drawdown: 12` 使用搭建器的百分数单位，工厂构建时除以 100；因子阈值直接使用原始比例，例如 `0.05` 表示 5%。

Lab 界面当前默认账户为 10 万元、最多 5 只、每笔预算 2 万元（含费用），按 100 股取整，单票一笔，沿用既有成本和 T+1 约束。这些账户参数属于运行配置，不包含在策略定义 JSON 内。若多只股票同时满足条件，现有账户引擎按代码顺序买入；这里没有综合因子排序，也没有行业分散约束。20 日是持仓期限上限，不是每月统一调仓日；出场后仍满足买入条件时，现有引擎可能当天再次买入同一股票。

## 保存与使用

本次生成的策略已保存到当前工作区 `data/lab/strategies/`，在使用此目录的 Lab 中打开「回测配置 → 自由搭建 → 策略库」，选择「中期动量低波动（研究基线）」即可编辑或运行。若服务在其他目录或 Docker 独立数据卷运行，需要向该服务导入配置。

配置文件本身就是 `POST /api/builder/strategies` 的请求体。在项目根目录执行下例可以向本地服务另存一份新策略；每次调用创建新的策略身份，不更新已有策略：

```sh
curl --fail-with-body http://127.0.0.1:8765/api/builder/strategies \
  -H 'Content-Type: application/json' \
  -H 'Origin: http://127.0.0.1:8765' \
  --data-binary @strategies/configs/momentum_low_volatility.json
```

实际服务地址不同时，同时调整 URL 与 Origin。使用现有界面，无需重新编译前端来显示已保存的策略；策略库需刷新读取。

## 验证与研究要求

自动化测试 `TestMomentumLowVolatility*` 覆盖配置可运行、上涨序列入场、历史不足拒绝、因子拒绝场景、成交额缺失、只读确定性、三种独立风控、趋势退出及策略库保存恢复。

```sh
TZ=Asia/Shanghai go test ./internal/lab -run '^TestMomentumLowVolatility' -count=1
```

真实研究先固定股票池、参数、训练区间和测试区间，不根据测试收益反复修改。至少查看跨市场阶段的账户净收益、最大回撤、基准超额、换手、交易数、成本拖累，以及去掉单个因子后的变化；成本压力测试应使用原成本与加倍成本。只读研究结果应写入 `output/` 对应模块目录。缺少历史退市股票、复权/公司行动和历史成分信息时，需要披露覆盖与生存偏差，不能把当前股票列表当作历史完整样本。

普通自由搭建回测当前按收盘信号、同收盘买入，分钟卖出时使用当时的当日快照；它不能证明本策略可在最终收盘信息已知后成交。正式评估还需要冻结收盘信号并验证下一交易时点成交、涨跌停/停牌约束。仓库组合研究层有独立执行与证据准入协议，不能跳过该协议把这份阈值策略直接标为通过验证的组合模型。
