# tdx v2 本地迁移

本仓库已从 `github.com/injoyai/tdx v0.0.87` 迁到 `github.com/injoyai/tdx/v2`。迁移包括客户端、价格类型、策略和旧数据读取；尚未接入 MySQL，也没有部署到运行中的服务。

## 开发与构建

目录需要保持同级：

```text
项目/
  strategy-tail/
  tdx/                 # module github.com/injoyai/tdx/v2
```

`go.work` 同时使用这两个模块；`go.mod` 的相对 `replace` 保证关闭工作区时也使用同一份本地 SDK。清单中的 `v2.0.0` 不代表已验证同名远程发布可用。当前构建依赖本地 SDK 的实际源码，单独复制 strategy-tail 不能构建。原有 `third_party/injoyai-base` 修补依赖继续保留。

```sh
go list -m github.com/injoyai/tdx/v2
TZ=Asia/Shanghai CGO_ENABLED=0 go test ./core ./lib/... ./strategies/... ./internal/... ./cmd/... ./researchdata/... .
go vet . ./core/... ./lib/... ./strategies/... ./internal/... ./cmd/... ./researchdata/...
docker build --build-context tdx=../tdx --build-arg GOPROXY=https://proxy.golang.org -t strategy-lab .
```

`deploy.sh` 已传入命名构建上下文，但本次未执行部署。测试命令显式列出维护中的源码目录：`output/` 下用户保留的历史 Go 实验程序不属于本次业务回归范围。

## 价格、时间和成交量

- 行情、交易价格、滑点和价格指标使用 `float64` 原币种值，A 股为元，指数为点；成交额同样使用元。配置中的滑点本来就以元输入，无需修改配置值。
- v2 统一行情的时间是源日期字符串。现有 A 股回测仍使用标准协议的 `time.Time`；`lib/extend/client.go` 显式读取原始标准记录，保留交易时刻，不把日线改成零点。
- 策略层成交量保持整数手，适配层调用 SDK `Klines()`；不能无损转换为整数手时返回错误。原始协议记录保持不变。指数使用普通分钟入口，股票的集合竞价拆分使用 241 分钟入口。
- 长历史直接传递 K 线列表，不再借用旧协议的 `uint16 Count` 承载累计数量。
- 本次适配继续服务现有中国标准市场策略。港美股和期货的交易时段、成交量、费用、仓位与 T+1 规则未因此自动获得支持。

## 旧文件如何处理

原有默认目录仍为 `data/database`，未批量改写行情库。

| 数据 | v2 行为 | 回退限制 |
| --- | --- | --- |
| 旧日线、未压缩分钟 SQLite | `Close` 声明为整数列时，读取价格和成交额除以 1000；写入同库时按最近整数厘取整，保留旧格式精度 | 旧列保持原格式和 0.001 精度；更高精度需使用新浮点列 |
| `user_version=101`、KLM1 压缩分钟库 | 继续读取整数厘块 | 增量写入后事务内标记为 102 |
| 新压缩分钟库 | `user_version=102`、KLM2，价格和金额保存 IEEE 754 浮点位，整数计数和时间仍保存整数 | 旧版程序不能读取 102；需保留升级前备份 |
| 101 库的增量更新 | 更新涉及的块写为 KLM2，其余 KLM1 块保留；读取支持两种块共存 | 不做全库重编码；已压缩库的压缩命令不会重新压缩 |
| 盘感练习私有行情、会话与题库 JSON | 新文件带 `priceUnit: "yuan"`；旧文件无标记时只转换原整数厘字段，既有浮点指标不缩放 | 未知单位拒绝读取；新文件不能直接交给旧版程序 |
| 页面、回放和导出的价格 | 对外仍是元值 | Go 内部 `Trade` 等价格字段类型及其直接 JSON 数值已改变；直接使用这些内部结构的调用方必须同步升级 |

不要通过删除单位标记、修改 `user_version` 来强行回退。保留旧副本并同时回退程序与数据。

## 指标精度与回测差异

旧价格类型是整数厘，均线、部分指标和逐股费用计算会发生整数截断。v2 采用浮点计算，不保留这类截断。阈值附近的信号和成交结果可能变化，不能把版本前后结果当作同一算法的严格相等基线。

本次使用同一份只读样本副本验证：12 只股票、50,897 根历史日线、1,980,695 根 2024–2026 年分钟线。将旧单位归一后，12 份完整输入哈希全部相同。

参考策略为 MA5 > MA20 买入、买入后超过五个自然日卖出，单票最多一笔、每笔 100 股，使用默认成本。升级前后都得到 920 笔交易，其中 16 笔买卖时点不同：sh601399 为 7 笔，sz002414 为 9 笔。在 v2 输入上仅将信号改回旧整数均线，全部买卖时点恢复一致，说明这些时点变化来自均线精度。这个对照不证明所有策略、收益或成本逐位相同，也不是 MySQL 性能测试。

原冻结基线文件保留，新增 `_v2.json` 基线；均线相关的 `sell_below_short_ma`、`sell_long_ma_down`、`shanghai_ma` 三项哈希随精度变化更新。

机器可读明细与检查日志见本地 `output/tdx-v2/`。没有运行真实服务器全量拉取、改写现有行情库、MySQL 导入或线上部署。后续 MySQL Store 接入需要独立验证市场和资产类型映射，特别是美股股票、ETF、指数的分类。
